# S1-4 界面布局与信息架构

> 分析对象：Google Stitch
> 信息采集时间：2026-09-29
> 分析目标：拆解布局框架、功能区划分、导航体系、组件排布逻辑、视觉层级，总结底层设计逻辑

---

## 1. 界面形态的三次演进

理解 Stitch 的布局，必须先理解它经历了**三次形态跃迁**——这直接决定了我们应该对标哪一版。

| 阶段 | 时间 | 界面形态 | 布局特征 |
|---|---|---|---|
| **V1 对话式** | 2025.05 | 左右分栏 | 左侧对话栏 + 右侧画布；**无工具栏、无图层面板** |
| **V2 三段式** | 2025.12 | 三面板 | **提示词区 + 画布 + Agent 日志** |
| **V3 AI 原生画布** | 2026.03 | 无限画布 | 重构为 AI-native infinite canvas；想法从草图到原型在同一工作台内生长 |

### 1.1 V1/V2 形态（实测描述）🅱

> 「界面极其简洁：**左侧对话栏，右侧画布**。没有复杂的工具栏，没有图层面板，整个交互逻辑就是『聊天』——这本身就是一种颠覆。」

> 「Stitch 的界面把你的屏幕分成三个面板：**提示词区、画布、Agent 日志**。从 Lovable 或 v0 过来，会觉得有点散——小事，但你每次迭代都能感觉到。」

### 1.2 V3 形态（2026.03）

重构为**无限画布（infinite canvas）**——一个想法可以从早期草图一直生长到可运行原型，而无需切换工具。新增：
- **Voice Canvas**：直接对画布说话
- **Agent Manager**：并行探索多个设计方向而不丢失分支
- **Design Agent**：追踪整个项目历史、推理不同版本

### 1.3 对本项目的判断

> ⚠️ **关键取舍**：V3 的「无限画布 + 语音」是前沿形态，但**实现复杂度极高**（无限画布涉及坐标系统、缩放平移、虚拟化渲染；语音涉及实时音频链路）。
>
> **建议对标 V2 三段式布局作为基线**，理由：
> 1. 三段式（输入 / 画布 / 日志）结构清晰，信息分区明确，是成熟且被验证的布局范式
> 2. 本项目核心是「生成 + 编辑 + 导出」，与三段式的功能映射天然吻合
> 3. V3 的无限画布属体验增强而非核心能力，可列入 v2.0
>
> **同时吸收 V3 的两个关键理念**：① 工作台内闭环（不切工具）② 多方向并行探索（对应本项目的变体功能）

## 2. 整体布局框架（对标基线）

### 2.1 三段式主布局

```
┌──────────────────────────────────────────────────────────────────────┐
│  顶栏：项目名 │ 模式/模型切换 │ 设备版型 │ 导出 │ 设置 │ 用户          │
├──────────────┬───────────────────────────────────┬───────────────────┤
│              │                                   │                   │
│  左栏         │           中央画布                 │   右栏            │
│              │                                   │                   │
│  ┌────────┐  │   ┌─────────────────────────┐     │  ┌─────────────┐  │
│  │ 页面列表 │  │   │                         │     │  │  属性面板    │  │
│  │ 缩略图   │  │   │      画布区域            │     │  │             │  │
│  └────────┘  │   │   (页面/多屏/画布流)      │     │  │  位置/尺寸   │  │
│              │   │                         │     │  │  样式/布局   │  │
│  ┌────────┐  │   └─────────────────────────┘     │  │  交互/跳转   │  │
│  │ 图层树  │  │                                   │  └─────────────┘  │
│  │        │  │                                   │                   │
│  └────────┘  │                                   │  ┌─────────────┐  │
│              │                                   │  │  组件库      │  │
│  ┌────────┐  │                                   │  └─────────────┘  │
│  │ 对话/   │  │                                   │                   │
│  │ Agent   │  │                                   │                   │
│  │ 日志    │  │                                   │                   │
│  └────────┘  │                                   │                   │
├──────────────┴───────────────────────────────────┴───────────────────┤
│  底部：提示词输入框 │ 增强提示词 │ 生成 │ 变体档位                      │
└──────────────────────────────────────────────────────────────────────┘
```

### 2.2 区域功能映射

| 区域 | 对应 Stitch 能力 | 本项目功能 |
|---|---|---|
| **顶栏** | 模式切换、设备版型、Export | 项目名、模型切换、设备版型、导出、设置 |
| **左栏 · 页面列表** | 多屏管理 | 页面增删复制排序 + 缩略图导航 |
| **左栏 · 图层树** | ⚠️ Stitch **无图层面板**（实测明确指出） | **本项目补齐**——图层树是编辑体验的基础设施 |
| **左栏 · 对话/日志** | Agent 日志、对话迭代 | 生成记录 + 对话式修图 |
| **中央画布** | 画布区 | 三视图切换：单页编辑 / 多屏对比 / 画布流 |
| **右栏 · 属性面板** | ⚠️ Stitch 仅 Edit theme（全局） | **本项目补齐**——细粒度属性编辑（位置/尺寸/样式/交互） |
| **右栏 · 组件库** | ⚠️ Stitch 组件自动生成，用户不可手动插入 | **本项目补齐**——组件库面板 + 拖入实例化 |
| **底部输入区** | 提示词输入框（V1/V2 在画布中央，V3 在画布内） | 提示词输入 + **增强按钮** + 生成 + 变体档位 |

> **重要发现**：Stitch 刻意**舍弃了图层面板、属性面板、组件库面板**——这是它「极简、对话驱动」设计哲学的体现，也是它编辑能力弱的根因。
>
> 它的取舍是：**把复杂度交给对话，把界面留给画布**。
>
> 本项目**不能照搬这个取舍**——因为我们的核心差异化正是「实时可视化编辑」，必须有属性面板与图层树作为操作载体。

## 3. 布局设计的底层逻辑

### 3.1 Stitch 的布局哲学：极简优先，对话为中心

| 逻辑 | 具体表现 | 设计意图 |
|---|---|---|
| **去工具栏** | 「没有复杂的工具栏」 | 降低学习成本，非设计师用户不会被专业工具界面劝退 |
| **去面板** | 无图层、无属性面板 | 强制用户用自然语言而非参数调节来表达意图 |
| **单一交互通道** | 整个交互逻辑就是「聊天」 | 交互一致性极高——所有修改都走同一个入口 |
| **结果即入口** | 生成结果上方直接出现 Edit | 动作就近，减少寻找成本 |

### 3.2 这套逻辑的代价

| 代价 | 表现 |
|---|---|
| 编辑精度受限 | 无法精确调整某个元素的 padding，只能说「间距大一点」 |
| 批量操作依赖选择 | 只能靠 Shift 多选，无图层树可批量选中同类元素 |
| 无法精细控制 | 「可以复制 hex，但不能点进去调整」 |
| 不适合复杂项目 | 复杂 B 端页面「堆砌感严重、信息密度失控」 |

### 3.3 本项目的布局策略：保留优点，补齐短板

```
Stitch 布局哲学                       本项目布局策略
─────────────────                    ─────────────────────
极简、去工具栏            ──────▶    保留简洁顶栏，不堆砌工具
对话为第一交互            ──────▶    完整保留（底部输入区 + 对话日志）
结果即入口                ──────▶    完整保留（操作紧贴对象）
─────────────────                    ─────────────────────
无图层树                  ──────▶    ✚ 补齐：编辑的基础设施
无属性面板                ──────▶    ✚ 补齐：细粒度控制载体
无组件库面板              ──────▶    ✚ 补齐：组件复用能力
```

> **核心判断**：本项目的差异化不在「比 Stitch 更极简」，而在「**同时具备 Stitch 的对话效率与专业工具的控制精度**」。
>
> 即：**对话是快路径，面板是精确路径，两者并存而非互相替代。**

## 4. 视觉层级与信息权重

### 4.1 画布是第一视觉主体

| 层级 | 元素 | 权重设计 |
|---|---|---|
| **第一层** | 设计画布 | 占据最大面积（≥ 60% 宽度），最亮/最清晰，无边框干扰 |
| **第二层** | 提示词输入区 | 位置固定（底部或画布中央），视觉重量适中，是高频操作区 |
| **第三层** | 左右功能面板 | 低对比度背景，弱化视觉存在，需要时才被注意 |
| **第四层** | 顶栏 / 状态信息 | 最小视觉重量，仅在需要时查看 |

### 4.2 空间配比建议

| 区域 | 宽度占比 | 理由 |
|---|---|---|
| 左栏 | 220-260px | 页面列表 + 图层树，需容纳缩略图 |
| 中栏画布 | **flex 自适应（主体）** | 设计工作的核心区域 |
| 右栏 | 260-300px | 属性面板 + 组件库，需容纳表单控件 |

### 4.3 视觉风格基调（Material 体系推断）

Stitch 输出带明显「Google 味」——由 Material Design 体系训练而来 🅱：

| 维度 | 特征 |
|---|---|
| 色彩 | 明快、饱和适中，主色突出 |
| 圆角 | 统一的中等圆角（8-12px） |
| 阴影 | 克制，多用层级而非重阴影 |
| 字体 | 现代无衬线，层级清晰 |
| 间距 | 遵循 8px 栅格 |

**优点**：风格统一、有设计规范、不会太丑
**缺点**：⚠️ 「如果你不喜欢 Google 的风格，这个产品可能不和你的胃口」——**同质化是 AI 平均审美的代价**

> 本项目启示：应向用户提供**多套风格预设**而非单一风格，避免「AI 平均审美」问题。

## 5. 导航体系设计

### 5.1 Stitch 的导航层次（浅而扁）

```
Level 1：主控制台（项目列表 + Examples）
    │
    └─▶ Level 2：设计工作台（画布 + 对话）
            │
            └─▶ 模式切换（Standard / Experimental）—— 顶栏
            └─▶ 版型切换（Mobile / Web）—— 项目级
            └─▶ 原型预览 —— 独立视窗
```

**特点**：只有两层导航，极浅。用户从登录到开始设计只有 **2 步**。

### 5.2 本项目导航设计

采用同样扁平的结构，但增加必要的层级承载：

```
Level 1：项目首页（项目列表 + 示例 + 新建）
    │
    └─▶ Level 2：设计工作台
            ├─ 视图切换：单页编辑 / 多屏对比 / 画布流
            ├─ 页面切换：左栏页面列表
            ├─ 预览模式：原型交互预览
            └─ 设置面板：模型配置 / 偏好
```

> 关键原则：**保持 2 层导航，绝不加深**。设置类内容走**模态/抽屉**，不占导航层级。

## 6. 组件排布逻辑

### 6.1 三条排布原则（从 Stitch 提炼）

| 原则 | 说明 | 应用 |
|---|---|---|
| **操作紧贴对象** | 结果的编辑入口出现在结果上，非集中工具栏 | 选中元素 → 属性面板自动切换 + 浮动工具条 |
| **高频优先** | 提示词输入框占据黄金位置 | 底部输入区常驻可见 |
| **渐进披露** | 不常用的能力收进菜单（如 Prompt Guide 在「三个点」里） | 高级配置收进设置抽屉 |

### 6.2 本项目组件排布映射

| 高频操作 | 位置 | 理由 |
|---|---|---|
| 提示词输入 + 生成 | 底部常驻 | 最高频，需始终可达 |
| 增强提示词 | 输入框旁 | 与输入强关联 |
| 页面切换 | 左栏上部 | 多页面高频切换 |
| 图层选择 | 左栏下部 | 与页面列表形成「页面→图层」的缩进逻辑 |
| 属性编辑 | 右栏 | 选中即出现，就近操作 |
| 组件库 | 右栏（Tab 切换） | 与属性面板共用右栏，避免视觉拥挤 |
| 导出 | 顶栏 | 低频但重要，需始终可达 |

## 7. 结论：布局设计的五条可复用经验

| # | 经验 | 本项目采纳方式 |
|---|---|---|
| **B-1** | **画布必须是绝对视觉主体** | 中部 flex 自适应，左右栏固定窄宽 |
| **B-2** | **输入区占据黄金位置且常驻** | 底部常驻输入栏，含增强按钮 |
| **B-3** | **操作入口紧贴操作对象** | 选中元素触发浮动工具条 + 属性面板联动 |
| **B-4** | **导航保持扁平（2 层）** | 项目首页 → 工作台，设置走抽屉 |
| **B-5** | **低频能力收进菜单，渐进披露** | Prompt Guide 类内容入帮助菜单；高级参数入设置抽屉 |

### 需要对 Stitch 做修正的三点

| # | Stitch 的问题 | 本项目修正 |
|---|---|---|
| **F-1** | 无图层面板 → 批量选中同类元素只能靠 Shift | **补齐图层树**，支持按类型筛选 |
| **F-2** | 无属性面板 → 编辑精度不足 | **补齐属性面板**，提供完整参数控制 |
| **F-3** | 单一 Google 风格 → AI 平均审美 | **提供多套风格预设**，支持自定义 Token |
