## 2. 演进时间线（关键：功能边界持续扩张）

| 时间 | 里程碑 | 能力变化 |
|---|---|---|
| 2025.05 | Google I/O 发布 | 文生 UI、图生 UI；Standard / Experimental 双模式；HTML/CSS 导出；Paste to Figma |
| 2025.12 | 接入 Gemini 3 + **Prototypes** | 从「单屏生成器」升级为「原型工具」：可串联多屏、定义转场、Play 预览 |
| 2026.03 | **Voice Canvas / Vibe Design / Direct Edits** | 界面重构为 AI-native 无限画布；语音对话设计；风格化批量探索；**支持直接手动微调文本与图片**；Design Agent 追踪项目历史；Agent Manager 并行探索多方向 |

> **判断**：这一条时间线对本次复刻至关重要——它说明 Stitch 的定位经历了三次跃迁：**UI 生成器 → 原型工具 → AI 原生设计工作台**。本项目的目标是复刻其**核心产品能力与交互体验**，因此对标基线应锁定在 2026.03 形态，而非 2025.05 的初版。

## 3. 目标用户画像

### 3.1 核心用户（Stitch 主推）

| 画像 | 核心诉求 | 使用频次 | 关键场景 |
|---|---|---|---|
| **产品经理 / 创业者** | 快速可视化想法，用于沟通与验证 | 中频 | 会议前生成 Demo、向投资人或团队展示概念 |
| **独立开发者 / 全栈一人** | 无设计预算但要产品不廉价 | 中高频 | MVP 搭建、UI 脚手架生成 |
| **前端开发者** | 不想在 CSS 调像素上耗时 | 中频 | 拿干净前端骨架直接改业务逻辑 |
| **UI/UX 设计师（早期探索）** | 接需求初期快速铺方向 | 高频 | 生成 5-10 个方向与客户对齐「感觉」 |

### 3.2 明确不适用的用户

| 画像 | 不适用原因 |
|---|---|
| 大型 B 端产品设计师 | 复杂信息架构、权限系统、数据优先级处理能力弱 |
| 需高保真交互的 UX 设计师 | 输出偏静态，无真实交互逻辑，不足以做可用性测试 |
| 追求品牌独特性的创意总监 | AI 输出的是「符合当代审美的平均值」，反而阻碍差异化 |

## 4. 核心使用场景

| 场景 | 描述 | Stitch 是否擅长 |
|---|---|---|
| 概念验证（MVP） | 从想法到可展示原型 | ✅ 强 |
| 创意发散 | 一次生成多方向供挑选 | ✅ 强（Vibe Design 强化） |
| 草图转 UI | 手绘草图/截图 → 高保真界面 | ✅ 强（杀手级） |
| 竞品结构拆解 | 上传竞品截图反向生成可编辑版本 | ✅ 强 |
| 可点击原型演示 | 多屏串联 + 转场预览 | ✅ 中（2025.12 后具备） |

| 设计系统级管理 | 跨项目组件库与 Token 统一 | ❌ 弱 |

## 5. 价值主张

### 5.1 一句话价值主张

> **消除「想法」与「可用界面」之间的技能门槛与时间成本——会说话就能做设计。**

### 5.2 价值拆解

| 价值维度 | 具体表述 | 支撑证据（可信度） |
|---|---|---|
| **技能去门槛** | 不需要懂 Figma、CSS 或设计原则 | 🅱 实测：PM/创业者可独立产出「看起来专业」的界面 |
| **速度** | 从需求到高保真原型由 1-2 天压缩至几分钟 | 🅱 实测：单页生成 40 秒内，理解提示词约 10 秒 |
| **修改成本极低** | 改风格从「重做调色板+查对比度+同步组件库」变为「一句话」 | 🅱 实测：深色模式+电光蓝精准应用无遗漏 |
| **质量兜底** | 即使不满意也不会丑得离谱，符合当代设计规范 | 🅱 多来源一致 |
| **隐含需求理解** | 不是机械执行指令，会补全常识性设计决策 | 🅱 实测：仅说「项目管理仪表盘」，自动补出任务状态/进度可视化/快捷入口 |

### 5.3 三个「惊艳点」的本质归纳

1. **隐含需求补全**——把「有 3 年经验设计师的常识」内化进模型
2. **迭代经济学改写**——修改边际成本趋近于零，鼓励更多探索、减少「将就」
3. **质量下限保障**——Gemini 对大量优秀设计案例的学习，形成「不会太差」的底线

## 6. 赛道差异化定位

### 6.1 竞品格局

| 产品 | 核心定位 | 输出物 | 迭代方式 | 与 Stitch 的关键差异 |
|---|---|---|---|---|
| **Google Stitch** | AI UI 生成 + 原型 | 视觉设计 + HTML/CSS | 对话 + 直接编辑 | 视觉质量强，路径到生产代码较弱 |
| **Figma Make** | 嵌入现有设计工具 | 可编辑设计稿 | 图形化直接编辑 | 优势在于「能抓住矩形拖动」，编辑自由度远高 |
| **v0 (Vercel)** | 设计到代码 | 生产级代码 | 代码层迭代 | 到生产的路径最短，视觉「设计感」弱 |
| **Lovable** | 全栈应用生成 | 可运行应用 | 代码层迭代 | 含后端与业务逻辑，Stitch 只给界面壳 |
| **Uizard** | 线框图生成 | 低保真线框 | 图形化编辑 | 保真度低，Stitch 直接高保真 |
| **Framer AI** | 网站生成 | 可发布网站 | 可视化编辑 | 面向网站，Stitch 面向 App UI |

### 6.2 Stitch 的差异化三角

```
                    视觉质量高
                        ▲
                       ╱ ╲
                      ╱   ╲
                     ╱ Stitch╲
                    ╱         ╲
                   ╱           ╲
    多模态输入 ◀───╱─────────────╲───▶ 免费无门槛
   (文/图/草图/语音)
```

三个顶点构成了 Stitch 的护城河，也是它区别于所有竞品的地方：

1. **视觉质量高**：Gemini 学习大量优秀案例，输出带「Material 味」的统一审美
2. **多模态输入**：文本 / 图片 / 手绘草图 / 语音，四类输入全覆盖（竞品多为文本单一入口）
3. **免费无门槛**：仅需 Google 账号，无订阅、无信用卡

### 6.3 一个被反复指出的定位误区

> Stitch **不是** Lovable / Bolt——它只生成 HTML/CSS 前端代码，**没有数据库、没有用户认证、没有业务逻辑**。
>
> 这是最需要向用户澄清的边界：**Stitch 给的是「界面壳子」，里面的逻辑需要开发者填充。**

## 7. 能力边界与适用范围

### 7.1 能力上限（硬边界）

| 边界 | 具体表现 | 对我们的启示 |
|---|---|---|
| **只到前端 UI** | 无后端、无数据、无认证 | 本项目定位一致，不越界 |
| **交互是「视觉态」非「逻辑」** | 点击按钮不会真的触发状态变化；给的是「点击前/后」两张图 | **本项目可做出差异化**：实现真实可交互预览 |
| **设计一致性依赖提示词** | 第一页主色电光蓝，第二页可能变靛蓝，除非显式指定 | **本项目可做出差异化**：用设计 Token 强制一致性 |
| **复杂信息架构弱** | B 端多层级导航/复杂表格易堆砌、密度失控 | 不做强项竞争，标注适用边界 |
| **无动画与微交互** | 输出为静态，无 micro-interaction | 本项目 v1.0 同样不做，列入 v2.0 |
| **无障碍不一致** | 对比度、触控目标尺寸不一定符合 WCAG | 本项目生成时加入基础对比度约束 |
| **默认英文文案** | 界面文字默认英文，实测多次要求切中文成功率低 | **本项目天然优势**：中文优先 |

### 7.2 成熟度定性

- **生成质量**：简单/模式化页面 90 分；多状态交互 75 分；复杂 B 端 60 分（🅱 实测评分）
- **输出保真度**：偏**中保真 Mockup**，而非可直接交付的成品；间距/对齐/图标常需二次精修
- **产品定位自评**：官方与实测一致认为它是**加速器不是替代品**

## 8. 对本项目的结论性启示

| # | 启示 | 影响阶段 |
|---|---|---|
| I-1 | **对标基线锁定 2026.03 形态**（AI-native 画布 + 直接编辑 + 多屏原型），而非初版单屏生成器 | S2 交互规范 |
| I-2 | Stitch 最大的三个短板（无真实交互、设计一致性弱、中文支持差）恰好是本地客户端可做出差异化的地方 | S2 功能规划 |
| I-3 | 「界面壳子」定位要清晰传达，避免用户误解为可生成完整应用 | 产品文档 |
| I-4 | 用户核心痛点是**提示词质量决定输出质量**——这直接支撑本项目的提示词增强功能（F-PE-01） | S2-5 / S3-3B |
| I-5 | Stitch 的配额限制（350/50 次每月）是云端产品的固有约束；本地客户端**无配额限制**是核心优势 | 产品价值主张 |
| I-6 | 免费是 Stitch 的护城河但依赖 Google 战略；Labs 项目有被砍历史，用户存在「成果存续」焦虑——本地运行天然消除此焦虑 | 产品价值主张 |
