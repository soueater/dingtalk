## ① 输入模块

### 1.1 文字提示输入

| 要素 | 内容 |
|---|---|
| **触发条件** | 进入项目后，画布中央常驻提示词输入框 |
| **输入** | 自然语言描述（建议包含：App 类型、版型、功能页面、视觉风格、目标用户） |
| **输出** | 提交给生成引擎的结构化意图 |
| **能力上限** | 建议长度约 200 词内效果最佳；**中文可接受但生成耗时变长**，且输出文案默认英文 |

**Prompt 结构化框架（官方推荐 Zoom-Out-Zoom-In）** 🅱

| 要素 | 示例 |
|---|---|
| APP 类型 | 健身追踪 App |
| 版型 | Mobile |
| 功能页面 | Dashboard、记录页、图表页 |
| 视觉风格 | 深色主题、绿色强调 |
| 目标用户 | 20-35 岁健身爱好者 |

### 1.2 图片 / 草图输入

| 要素 | 内容 |
|---|---|
| **触发条件** | 仅 **Experimental Mode** 下显示图片上传按钮 |
| **输入** | 手绘草图 / 线框图 / 竞品截图 |
| **输出** | 结构识别后生成的高保真 UI |
| **能力上限** | ⚠️ **草图清晰度直接决定结果**——实测潦草草图会漏掉元素（如漏掉按钮）；⚠️ 该模式下**不支持 Paste to Figma**，仅能导出 HTML/CSS |

> 定位：被称为「**杀手级功能**」——对习惯纸笔思考的设计师，打通了「草图 → 高保真」最短路径 🅱

### 1.3 语音输入（Voice Canvas）

| 要素 | 内容 |
|---|---|
| **触发条件** | 2026.03 版本新增，在无限画布中直接说话 |
| **输入** | 语音指令（如「给我三种不同的菜单布局」「把这屏改成深色系」） |
| **输出** | 实时的设计更新；AI 会**主动反问澄清**、给出实时设计点评 |
| **能力上限** | 属实验特性；对话式交互比点击式更快，但依赖模型理解准确度 |

## ② AI 生成模块

### 2.1 单屏生成

| 要素 | 内容 |
|---|---|
| **触发条件** | 输入提示词后点击「Generate designs」 |
| **输入** | 文字提示（+ 可选参考图） |
| **输出** | 完整 UI 界面（含导航栏、卡片、按钮等组件，自动处理配色与字体） |
| **能力上限** | 简单/模式化页面约 90 分；多状态交互约 75 分；复杂 B 端约 60 分 |

**性能基线** 🅱

| 模式 | 模型 | 理解耗时 | 生成耗时 | 总时长 |
|---|---|---|---|---|
| Standard | Gemini 2.5 Flash | ~10 秒 | ~40 秒 | **< 1 分钟** |
| Experimental | Gemini 2.5 Pro | — | — | **60-90 秒** |

### 2.2 多屏生成

| 要素 | 内容 |
|---|---|
| **触发条件** | 提示词中明确要求生成多个页面 |
| **输入** | 含多页面描述的单条提示词 |
| **输出** | 一组多屏界面（如底部导航三个板块一次生成） |
| **能力上限** | ⚠️ **跨屏一致性弱**——实测「所有页面的 Tabbar 都高亮了第一个图标」；⚠️ 需在提示词中显式要求「使用与上一页相同的配色系统」才能维持一致 |

### 2.3 多变体生成（Variants）

| 要素 | 内容 |
|---|---|
| **触发条件** | 主动要求生成多个版本，或 Vibe Design 模式下自动触发 |
| **输入** | 提示词 + 变体参数 |
| **输出** | 1-5 个设计变体 |

**可变化维度（接口级定义）** 🅰

| 参数 | 取值 |
|---|---|
| `variantCount` | 1-5 |
| `creativeRange` | `EXPLORE`（发散）等 |
| `aspects` | `LAYOUT` / `COLOR_SCHEME` / `IMAGES` / `TEXT_FONT` / `TEXT_CONTENT` |

> **接口级信息**（来自官方 SDK）：`screen.variants(prompt, options)` 返回多个设计替代方案。这是「一次探索多方向」能力的底层支撑。

### 2.4 风格化探索（Vibe Design）

| 要素 | 内容 |
|---|---|
| **触发条件** | 2026.03 新增；不指定具体组件，而描述业务目标或期望感受 |
| **输入** | 氛围描述（如「高级极简，像 Stripe」「科技感、专业、让人信任」） |
| **输出** | **多个不同设计方向**（实测：一次生成霓虹赛博朋克 / 极简苹果 / 暖色复古 三种风格） |
| **能力上限** | 极大加速早期创意发散（传统做 3 个方向需半天）；但最终选择与细化仍需人的审美判断 |

### 2.5 流程自动生成（Canvas Flow）

| 要素 | 内容 |
|---|---|
| **触发条件** | 2025.12 随 Prototypes 引入 |
| **输入** | 整体应用描述 |
| **输出** | 完整的页面导航结构 + 逻辑关系连接 + 自动生成合理的后续屏幕 |
| **能力上限** | 能理解页面间逻辑关系并建立导航结构；复杂业务流仍需人工调整 |

### 2.6 设备/版型选择

| 要素 | 内容 |
|---|---|
| **触发条件** | 新建设计时选择 |
| **输入** | 设备类型 |
| **输出** | 对应尺寸的画布 |

**设备类型（接口级定义）** 🅰

| 类型 | 说明 |
|---|---|
| `MOBILE` | 移动端（实测生成效果**优于** Web） |
| `DESKTOP` | 桌面端 |
| `TABLET` | 平板 |
| `AGNOSTIC` | 响应式/不限定 |

## ③ 可视化编辑模块

### 3.1 直接编辑（Direct Edits）

| 要素 | 内容 |
|---|---|
| **触发条件** | 2026.03 新增，选中画布元素后直接操作 |
| **输入** | 手动操作：改文本、换图片、调细节 |
| **输出** | 即时更新的设计 |
| **能力上限** | ⚠️ **仅支持有限的直接编辑**——历史版本中「能复制 hex 但不能点进去调色」；属对「最受期待功能」的初步回应，成熟度仍不足 |

> **这是设计师反馈的最大摩擦点**：Stitch 输出本质是**只读预览 + 提示词驱动编辑**，无法像 Figma 那样「抓住一个矩形拖动」。🅱

### 3.2 主题编辑（Theme Editor）

| 要素 | 内容 |
|---|---|
| **触发条件** | 页面右上角「Edit theme」入口 |
| **输入** | 调整色彩、边框圆角、字体、间距；支持明暗主题切换 |
| **输出** | 主题变更**作用在当前所有图上** |
| **能力上限** | ⚠️ **Experimental Mode 下该功能置灰不可用**；⚠️ 无法细粒度改单个色值 |

### 3.3 多选批量修改（Multi-Select）

| 要素 | 内容 |
|---|---|
| **触发条件** | 按住 `Shift` + 点击选取多个画面 |
| **输入** | 一条提示词，作用于所有选中页面 |
| **输出** | 批量应用修改 |
| **能力上限** | ✅ 解决「十几个页面套用同样变更」的重复劳动，是保持设计一致性的关键工具 🅱 |

> 实测场景：「把整个 App 的主色调从蓝色改成绿色」「调整所有按钮的圆角大小」——几秒完成。

### 3.4 对话式迭代

| 要素 | 内容 |
|---|---|
| **触发条件** | 生成结果上方「Edit」按钮，在左下角输入框继续对话 |
| **输入** | 自然语言修改指令 |
| **输出** | 即时更新的设计 |
| **能力上限** | ✅ **这是 Stitch 的核心优势**——上下文理解极强，能精准定位「悬浮按钮」「底部导航激活态」等相对位置描述；「专业深色模式」能理解应偏冷而非暖灰 🅱 |

## ④ 原生组件与设计体系

### 4.1 内置组件库

| 要素 | 内容 |
|---|---|
| **触发条件** | 由生成引擎自动调用，用户无需手动插入 |
| **输入** | 页面结构与组件需求（从提示词推导） |
| **输出** | 标准化 UI 组件（导航栏、卡片、按钮、图表、表单、列表等） |
| **能力上限** | ✅ 风格统一，带明显「Google 味」（由 Material 体系训练而来）；⚠️ **不喜欢 Google 风格的用户会不适**；⚠️ **默认无组件命名与设计系统结构**，导出后组件是散的 |

### 4.2 设计系统导入（design.md / DMD）

| 要素 | 内容 |
|---|---|
| **触发条件** | 提供 design.md 设计系统文件 |
| **输入** | 纯文本格式的设计系统蓝图：色值、字体、间距、组件规则，**以及「不要做什么」的负面规则** |
| **输出** | 生成结果遵循该设计系统 |
| **能力上限** | 实测有效：无 design.md 时 Stitch「自己发明了绿色、把主按钮用错颜色」；提供后字体锁定正确、色板回归真实 🅱 |

> **重要洞察**：design.md 概念**不局限于 Stitch**——同一份文件可用于 Claude Code、v0 等任何 AI 设计工具，是「跨工具一致性的共享事实源」。
>
> 负面规则（don'ts）价值极高：「不要用全大写标题」「不要堆叠超过两个 CTA」「不要在破坏性操作上使用强调色」——显式 don'ts 能显著降低劣质生成。

> ⚠️ 注：Design Systems（从 URL 自动导入 Token）在 2026.03 时点仍属**测试中**功能。

| **能力上限** | 支持 Mobile / Desktop / Tablet 三种版型预览 |

### 5.2 跳转连接与转场（Prototypes）

| 要素 | 内容 |
|---|---|
| **触发条件** | 2025.12 新增；在原型模式下连接屏幕 |
| **输入** | 屏幕间的导航关系 + 转场定义 |
| **输出** | 可点击预览的完整用户旅程（点 Play 播放） |
| **能力上限** | ⚠️ **关键边界**：这里的「可点击」是**视觉状态展示**，不是可运行的交互逻辑——点击按钮不会真的触发状态变化，表单提交不会校验输入。本质是「点击前/后」两张图的切换 🅱 |

> **这是 Stitch 的第一个天花板：它生成的是 UI，不是 App。**
>
> 同时也是**本项目最重要的差异化机会点**——可以实现真实的交互预览。

| **输出** | AI 根据标注自动修改 |
| **能力上限** | ⚠️ 2026.03 时点仍为**测试中**功能 |

## ⑥ 导出与分享模块

### 6.1 代码导出

| 要素 | 内容 |
|---|---|
| **触发条件** | 点击 Export |
| **输入** | 已生成的设计 |
| **输出** | 干净的前端代码 |

**导出格式（接口级定义）** 🅰

| 格式 | 说明 |
|---|---|
| HTML/CSS | 使用 **Tailwind CSS**；可复制使用 |
| React / JSX | 支持 React 格式 |
| 完整素材包 | 代码 + 图片素材打包（ZIP） |
| 获取方式 | `screen.getHtml()` 返回**下载 URL**（非裸 HTML，需再 fetch） |

| 能力上限 |
|---|

| ⚠️ 官方明确 **暂无 REST API**，仅 SDK / MCP 可用 |
| ⚠️ 生成的代码「可用但不总是生产级」，需开发者审查清理 |

## ⑧ 功能能力上限汇总（关键约束清单）

| # | 约束 | 严重度 | 本项目应对方向 |
|---|---|---|---|
| C-1 | 只生成前端 UI，无后端/数据/认证 | 设计边界 | 保持一致，明确传达 |
| C-2 | 交互是视觉态非真实逻辑 | **高** | **差异化：实现真实可交互预览** |

| C-5 | 复杂 B 端信息架构处理弱 | 中 | 标注适用边界 |

| C-8 | 默认英文文案，中文支持差 | 中 | **差异化：中文优先** |
| C-9 | 配额限制（350/50 次每月） | 中 | **差异化：本地无配额** |

| C-12 | Experimental 模式功能阉割（无 Figma 导出、无主题编辑） | 低 | 本项目不设模式阉割 |
| C-13 | 云端产品存续风险（Labs 项目有被砍历史） | 低 | **差异化：本地运行，成果自主** |
| C-14 | 仅英文界面 | 低 | **差异化：中文界面** |

## ⑨ 结论

**Stitch 的功能广度已经相当完整**——从输入（四类模态）→ 生成（单屏/多变体/多屏/风格探索）→ 编辑（直接编辑/主题/多选/对话）→ 组件体系 → 原型（跳转/转场/预览）→ 导出（代码/Figma/下游工具）→ 项目管理，形成闭环。

**但其深度存在明显断层**，集中在三处：**编辑自由度**（只读预览）、**交互真实性**（视觉态非逻辑）、**一致性保障**（依赖提示词）。

这三处断层，恰好构成本项目本地客户端复刻时的**功能取舍依据与差异化空间**——详见 `S1-5-结论与落地建议.md` 的功能取舍矩阵。
