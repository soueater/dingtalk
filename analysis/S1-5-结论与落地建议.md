## 1. 核心设计亮点与可复用经验

### 1.1 七个亮点（按复用价值排序）

| # | 亮点 | 本质 | 复用价值 | 复用方式 |
|---|---|---|---|---|
| **H-1** | **一次生成多个变体** | 把「选择」作为默认路径，而非「重试」 | ⭐⭐⭐⭐⭐ | 直接复刻。降低迭代挫败感的关键设计 |
| **H-2** | **对话式迭代的上下文理解** | 能精准定位「悬浮按钮」「底部导航激活态」等相对位置 | ⭐⭐⭐⭐⭐ | 直接复刻。这是 AI 设计工具相对传统工具的核心优势 |
| **H-3** | **全局修改优先于逐个修改** | Edit theme 作用于所有图；Shift 多选批量改 | ⭐⭐⭐⭐⭐ | 直接复刻，并强化为设计 Token 机制 |
| **H-4** | **零摩擦启动** | 无等待名单、无引导流程、登录即用 | ⭐⭐⭐⭐ | 适配为「双击即进主界面」，不设登录墙 |
| **H-5** | **三层递进式引导** | 示例案例 → 输入框范例 → Prompt Guide | ⭐⭐⭐⭐ | 复刻并升级为「提示词增强」，从「给答案」到「改作业」 |
| **H-6** | **动作就近原则** | 编辑入口紧贴生成结果，不集中工具栏 | ⭐⭐⭐⭐ | 直接复刻：选中元素 → 浮动工具条 + 面板联动 |
| **H-7** | **设计系统文件（design.md）** | 显式 don'ts 显著降低劣质生成 | ⭐⭐⭐ | **升级为设计 Token 机制**，同时解决 Stitch 的跨屏一致性问题 |

### 1.2 三个「难以复制但值得借鉴」的能力

| 能力 | 为何难复制 | 借鉴方式 |
|---|---|---|
| Gemini 对优秀设计案例的学习 | 依赖 Google 的模型与数据积累 | 通过 Prompt 工程 + 设计 Token 约束，在通用模型上逼近效果 |
| 多模态输入（草图/截图识别） | 需要视觉理解能力 | v1.0 先做文字输入；图片输入列入 v2.0（可复用支持视觉的模型） |
| 语音对话设计（Voice Canvas） | 需实时音频链路 | 列入 v2.0 |

## 2. 现存体验痛点与优化空间

### 2.1 痛点清单（按严重度排序）

| # | 痛点 | 严重度 | 用户影响 | 根因 |
|---|---|---|---|---|
| **P-1** | **交互预览是「视觉态」非真实逻辑** | 🔴 高 | 点击按钮不触发状态变化，无法做可用性测试 | 输出的是静态 UI 的多状态图，未构建交互模型 |
| **P-2** | **编辑能力有限，本质只读预览** | 🔴 高 | 「能复制 hex 但不能点进去调整」，设计师最大摩擦点 | 刻意舍弃图形化编辑，全押对话通道 |
| **P-3** | **跨屏设计一致性弱** | 🔴 高 | 第一页电光蓝、第二页变靛蓝，需提示词显式约束 | 无跨页设计系统强制机制 |
| **P-4** | **仅英文界面，中文输出差** | 🟡 中 | 中文输入耗时增加，输出文案仍为英文 | 产品国际化未覆盖中文 |
| **P-5** | **无图层/属性/组件面板** | 🟡 中 | 无法精确调整、无法复用组件、批量选择受限 | 极简哲学的代价 |
| **P-6** | **复杂 B 端信息架构能力弱** | 🟡 中 | 多层级导航/复杂表格堆砌感严重、密度失控 | 模型对信息优先级的理解不足 |
| **P-7** | **生成结果偏中保真，需二次精修** | 🟡 中 | 间距/对齐/图标需人工调整 | 输出定位为 Mockup 而非成品 |
| **P-8** | **单一样式风格（Google 味）** | 🟢 低 | 不喜欢 Material 风格的用户不适；AI 平均审美导致同质化 | 由 Material 体系训练而来 |
| **P-9** | **无动画与微交互** | 🟢 低 | 静态输出 | 未构建动画能力 |
| **P-10** | **配额限制（350/50 次每月）** | 🟢 低 | 重度使用捉襟见肘 | 云端服务成本约束 |
| **P-11** | **云端产品存续不确定** | 🟢 低 | Labs 项目有被砍历史，用户存在成果存续焦虑 | Google 战略不确定性 |

### 2.2 优化空间优先级

```
优先级判断：痛点严重度 × 本项目可实现性

P-1 真实交互 ────────────── 高严重度 + 可实现 → 【优先攻克】
P-2 编辑能力 ────────────── 高严重度 + 可实现 → 【优先攻克】
P-3 一致性保障 ──────────── 高严重度 + 可实现 → 【优先攻克】
P-4 中文支持 ────────────── 中严重度 + 天然优势 → 【顺手解决】
P-5 面板补齐 ────────────── 中严重度 + 可实现 → 【必做基础设施】
P-6 复杂B端 ─────────────── 中严重度 + 难实现 → 【标注边界，不做强项竞争】
P-10 无配额 ─────────────── 低严重度 + 天然优势 → 【自动获得】
P-11 本地运行 ───────────── 低严重度 + 天然优势 → 【自动获得】
```

## 3. 功能取舍矩阵（核心交付物）

### 3.1 取舍决策定义

| 决策 | 含义 |
|---|---|
| **1:1 复刻** | 能力与交互对标 Stitch，直接实现 |
| **适配改造** | 保留核心意图，因本地形态或技术差异调整实现路径 |
| **强化超越** | 在 Stitch 基础上明确提升，形成差异化优势 |
| **不实现** | v1.0 明确不做，说明理由与归属版本 |

## 4. 三个核心差异化点（本项目立身之本）

从取舍矩阵中，收敛出三个必须做扎实的差异化能力：

### 差异化 1｜完整的实时可视化编辑

| 维度 | Stitch | 本项目 |
|---|---|---|
| 编辑方式 | 对话为主，直接编辑有限 | **对话 + 拖拽 + 属性面板三通道并存** |
| 精度 | 只能说「间距大一点」 | 精确到 px 的位置/尺寸/样式控制 |
| 基础设施 | 无图层树、无属性面板 | 图层树 + 属性面板 + 组件库 |
| 历史管理 | 无完整 Undo/Redo | 完整操作历史栈 |

**为什么这是差异化**：设计师反馈的最大摩擦点就是「只能看不能改」。本项目让 AI 生成成为**起点**而非**终点**。

### 差异化 2｜真实可交互原型

| 维度 | Stitch | 本项目 |
|---|---|---|
| 跳转 | 视觉态切换（点击前/后两张图） | **基于 Schema 的真实交互逻辑** |
| 预览 | 播放式演示 | 可真实点击、真实跳转 |
| 用途 | 演示 | **可用性测试** |

**为什么这是差异化**：Stitch 被明确评价为「生成的是 UI，不是 App」。本项目在原型层面补上这一环。

### 差异化 3｜设计 Token 驱动的强制一致性

| 维度 | Stitch | 本项目 |
|---|---|---|
| 跨屏一致性 | 需提示词显式约束，易漂移 | **设计 Token 强制统一** |
| 风格来源 | 单一 Material 风格 | 多套预设 + 自定义 |
| 修改传播 | Edit theme 作用当前图 | **Token 变更全局传播** |

**为什么这是差异化**：解决 P-3 痛点，同时让多页面项目的设计质量下限大幅提高。

## 5. 对本地客户端形态的适配建议

### 5.1 云端能力 → 本地形态的转换

| Stitch 云端能力 | 本地形态转换 | 影响 |
|---|---|---|
| Google 账号登录 | **无登录，直接进入** | 零摩擦体验更进一步 |
| 云端项目存储 | **本地 `.dsproj` 文件** | 数据自主，无存续焦虑 |
| 生成配额（350/50/月） | **无配额** | 核心优势 |
| 公开只读分享链接 | **导出独立 HTML 文件** | 同等分享效果，且无需网络 |
| 一键 Paste to Figma | **导出 HTML/SVG** | 替代交付路径 |
| 云端模型（Gemini） | **用户自配任意模型** | 灵活性与隐私双赢 |
| 下游工具直达 | **导出标准 HTML** | 保持到开发的可衔接性 |

### 5.2 本地形态带来的额外能力

| 能力 | 说明 |
|---|---|
| **无限次生成** | 无配额约束，鼓励充分探索 |
| **数据完全本地** | 密钥、设计稿不上传，隐私保障 |
| **离线可用的编辑与导出** | 已有项目的编辑和导出无需网络 |
| **文件级版本管理** | 项目可与 Git 等版本工具结合 |
| **零部署启动** | 双击即用，无需浏览器与网络 |

### 5.3 需要额外设计的地方

| 挑战 | 应对 |
|---|---|
| 无云端算力 | 生成依赖用户自配模型，需内置 Mock 模式兜底 |
| 打包体积 | Electron 约 150MB+，提供免安装绿色版规避安装成本 |
| 模型能力差异 | 通过 Prompt 工程 + 严格 Schema 约束，压缩不同模型的输出波动 |

## 6. 对标基线确认

综合 S1-1 ~ S1-4 的分析，明确本项目的对标基线：

| 维度 | 对标基线 |
|---|---|
| **产品形态** | Stitch 2026.03 形态（AI 原生工作台理念） |
| **布局框架** | 三段式（左页面/图层 + 中画布 + 右属性/组件），**非**无限画布 |
| **交互主线** | 对话为快路径 + 面板为精确路径，双通道并存 |
| **生成粒度** | 多屏 + 多变体，与 Stitch 同等粒度 |
| **编辑能力** | **超越 Stitch**（拖拽级编辑） |
| **原型能力** | **超越 Stitch**（真实交互） |
| **导出能力** | **超越 Stitch**（PNG/SVG/HTML/JSON 四格式） |
| **风格体系** | **超越 Stitch**（多套预设 + Token 驱动一致性） |
