# S1-3 全链路交互流程还原

> 分析对象：Google Stitch
> 信息采集时间：2026-09-29
> 还原目标：从启动到交付的完整用户操作路径，逐步拆解**交互反馈 / 操作入口 / 异常处理 / 引导逻辑**

---

## 0. 全链路总览

```
启动 → 登录 → 项目创建 → 需求输入 → AI 生成 → 结果浏览 → 编辑调整 
  → 原型配置 → 导出交付
```

**各步骤耗时基线** 🅱

| 步骤 | 耗时 |
|---|---|
| 登录（首次） | 秒级，仅需 Google 账号 |
| 提示词理解 | ~10 秒（Standard Mode） |
| 单屏生成 | ~40 秒（Standard）/ 60-90 秒（Experimental） |
| 从需求到可展示原型 | < 30 分钟（含人工调整） |

---

## 步骤 1｜启动与登录

| 维度 | 内容 |
|---|---|
| **操作入口** | 浏览器访问 `stitch.withgoogle.com` |
| **交互反馈** | — |
| **引导逻辑** | ✅ **无需等待名单、无信用卡、无引导流程（no onboarding flow）**——实测「你直接落在画布上，就可以开始设计了」 |
| **异常处理** | 需满 18 岁；覆盖 212 个国家和地区 |
| **对标启示** | 秒级进入可用状态是重要体验基准——本项目客户端应做到**双击即进主界面**，不设登录墙 |

---

## 步骤 2｜项目创建

| 维度 | 内容 |
|---|---|
| **操作入口** | 主控制台 → 点击「Start a new design」 |
| **关键决策点** | ① 选择模式（Standard / Experimental）② 选择版型（Mobile / Web） |
| **交互反馈** | 进入 New Design 界面，右上角可切换模式，下方选择 Mobile 或 Web 版型 |
| **引导逻辑** | ✅ 主控制台展示**最近项目**与**官方 Examples**；「随便点开一个例子都能看到和 Stitch 交互的聊天记录」——用真实案例教学 |
| **异常处理** | ⚠️ Experimental Mode 功能受限（无 Figma 导出、主题编辑置灰），切换时需让用户可预期 |
| **对标启示** | 「示例即教程」是低成本高效果的引导手段；本项目应内置示例项目 |

> 实测经验：**Stitch 在手机界面的生成效果比网页好**。这是版型选择的隐含知识，官方未明示，属实测发现。

---

## 步骤 3｜需求输入

| 维度 | 内容 |
|---|---|
| **操作入口** | 画布中央的提示词输入框（`The prompt bar sits at the center of the canvas`） |
| **输入方式** | ① 文字提示 ② 图片上传（仅 Experimental）③ 语音（2026.03 Voice Canvas） |
| **交互反馈** | 输入框旁提供 **Prompt 范例参考**；右上角「三个点」→ **Prompt Guide** 提供撰写指南 |
| **引导逻辑** | ✅ **双层引导设计**，值得学习：<br>• **入口即引导**：输入框下方直接给 Prompt 示例，降低「第一句话怎么说」的启动阻力<br>• **深度即教程**：Prompt Guide 完整讲解 UI 专业形容词体系，面向想学好的用户 |
| **异常处理** | ⚠️ 中文输入可接受但耗时增加，且输出文案仍为英文 |
| **对标启示** | 这正是**提示词增强（F-PE-01）**要解决的痛点——Stitch 用「给范例」降低门槛，本项目用「自动转化」进一步消除门槛。**从「给答案」升级为「改作业」** |

### Prompt 撰写推荐结构（官方框架）

```
APP 类型 → 版型 → 功能页面 → 视觉风格 → 目标用户
```

---

## 步骤 4｜AI 生成

| 维度 | 内容 |
|---|---|
| **操作入口** | 输入框右下角「Generate designs」按钮 |
| **交互反馈** | ⏳ **等待态**：生成期间有明确耗时（Standard ~50 秒总耗时），用户可感知进度 |
| **输出形态** | **多个设计变体**同时呈现，点任一查看细节 |
| **异常处理** | ⚠️ Experimental Mode 约 90 秒，需更强的等待容忍设计 |
| **对标启示** | ✅ 「**一次生成多个变体**」而非单个结果，把「选择」而非「重试」作为默认路径——显著降低迭代挫败感。本项目应沿用 |

---

## 步骤 5｜结果浏览与选择

| 维度 | 内容 |
|---|---|
| **操作入口** | 画布上展示生成的多屏/多变体结果 |
| **交互反馈** | 点击任一结果查看细节；结果上方出现 **Edit 按钮** |
| **引导逻辑** | ✅ 生成结果自带「下一步动作」入口（Edit），不需要用户寻找编辑功能在哪 |
| **对标启示** | **动作就近原则**——操作入口紧贴操作对象，而非集中在远离的工具栏 |

---

## 步骤 6｜编辑调整（四条并行路径）

这是 Stitch 交互设计的核心区域，提供**四种互补的修改方式**：

### 路径 A｜对话式迭代（主力）

| 维度 | 内容 |
|---|---|
| **操作入口** | 结果上方 Edit → 左下角输入框 |
| **输入** | 自然语言修改指令 |
| **交互反馈** | 即时更新，无中间确认步骤 |
| **优势** | ✅ 上下文理解极强——能精准理解「悬浮的 + 按钮」「底部导航的激活态」等**相对位置描述**；能理解「专业深色模式」应偏冷色而非暖灰 |
| **异常处理** | 复杂指令可能部分执行，需用户逐步细化 |

**实测有效指令示例** 🅱

```
第一轮：This is a great start. Now, change the entire theme to 
a professional dark mode. Make the primary accent color a vibrant 
electric blue, and apply it to the floating '+' button, the active 
'Dashboard' icon in the bottom nav, and the 'Progress' bars.

追加：Add a tabbar at the bottom of the page.
```

> 实测结论：「完美执行，整个界面秒变深色模式，电光蓝精准应用在指定位置，没有错位、没有遗漏」

### 路径 B｜主题编辑（全局）

| 维度 | 内容 |
|---|---|
| **操作入口** | 页面右上角「Edit theme」 |
| **输入** | 色彩、边框圆角、字体、间距、明暗主题 |
| **交互反馈** | 变更**作用在当前所有图上** |
| **异常处理** | ⚠️ Experimental Mode 下置灰；⚠️ 无法细粒度改单个色值 |
| **对标启示** | ✅ 「一处修改，全局生效」是效率关键——尤其在生成了一组图时。本项目应强化为**设计 Token 机制** |

### 路径 C｜多选批量修改

| 维度 | 内容 |
|---|---|
| **操作入口** | 按住 `Shift` + 点击多个画面 |
| **输入** | 一条提示词，作用于所有选中页面 |
| **交互反馈** | 批量应用 |
| **对标启示** | ✅ 直接解决「重复劳动」痛点。本项目**必须复刻**此能力 |

### 路径 D｜直接编辑（有限）

| 维度 | 内容 |
|---|---|
| **操作入口** | 选中元素后直接操作 |
| **输入** | 改文本、换图片、调细节 |
| **交互反馈** | 即时更新 |
| **异常处理** | ⚠️ **能力有限**——历史上「可以复制 hex，但不能点进去调整」；本质是只读预览 |
| **对标启示** | ⚠️ **这是最大的体验痛点，也是本项目最大的差异化机会**——实现真正的拖拽级编辑 |

## 步骤 7｜原型配置

| 维度 | 内容 |
|---|---|
| **操作入口** | 2025.12 后进入原型模式 |
| **操作内容** | ① 连接屏幕 ② 定义转场 ③ 点 Play 预览完整用户旅程 |
| **交互反馈** | 专属原型预览视窗，支持 Mobile / Desktop / Tablet 三种版型切换 |
| **异常处理** | ⚠️ **关键限制**：预览中的「交互」是视觉状态切换，非真实逻辑——点击不会真的触发状态变化 |
| **对标启示** | **本项目可实现真实交互逻辑**（基于 Schema 中的 interactions 字段），这是明确的超越点 |

---

## 步骤 8｜导出交付

| 维度 | 内容 |
|---|---|
| **操作入口** | Export 按钮 / Paste to Figma |
| **可选目标** | ① HTML/CSS 代码 ② React/JSX ③ 素材包 ZIP ④ Figma ⑤ Google AI Studio ⑥ Firebase Studio ⑦ 公开只读链接 |
| **交互反馈** | 代码为**只读展示**，需复制使用；Figma 走剪贴板粘贴 |
| **异常处理** | ⚠️ Experimental Mode 无 Figma 导出；⚠️ 图片上传生成的设计不支持 Figma |
| **引导逻辑** | 官方推荐工作流：**用 Stitch 快速产概念 → 导出 Figma 精修 → 代码交开发** |
| **对标启示** | 本项目导出应**直接产出文件**（非只读展示 + 复制），且不设模式阉割 |

## 1. 全链路交互设计规律总结

从上述 8 个步骤中，可提炼出 Stitch 交互设计的 **7 条底层规律**：

| # | 规律 | 体现 |
|---|---|---|
| **L-1** | **零摩擦启动** | 无等待名单、无引导流程、登录即用 |
| **L-2** | **示例即教程** | Examples 案例 + 输入框内 Prompt 范例 + Prompt Guide 三层引导 |
| **L-3** | **动作就近** | 生成结果上方直接出现 Edit 按钮，入口紧贴对象 |
| **L-4** | **多结果优于单结果** | 默认生成多变体，把「选择」变成默认路径而非「重试」 |
| **L-5** | **对话为第一交互** | 自然语言迭代是主力修改方式，图形化编辑为辅助 |
| **L-6** | **全局修改优先于逐个修改** | Edit theme 作用于所有图、Multi-Select 批量改 |
| **L-7** | **导出即交付** | 直接对接 Figma / AI Studio，缩短到下游的距离 |

## 2. 异常与边界处理汇总

| 异常场景 | Stitch 的处理 | 评价 | 本项目改进方向 |
|---|---|---|---|
| 生成耗时长（60-90 秒） | 有等待态 | 一般，无明确进度 | **流式输出 + 逐页出现 + 骨架屏** |
| 多屏风格不一致 | ⚠️ 无自动保障，需提示词显式约束 | 差 | **设计 Token 强制一致性** |
| 草图不清晰导致漏元素 | ⚠️ 无提示，直接产出错误结果 | 差 | 输入质量提示 + 生成后校验 |
| 中文输出仍为英文文案 | ⚠️ 多次尝试切换成功率低 | 差 | **中文优先，原生支持** |
| Experimental 模式功能阉割 | 置灰 / 隐藏入口 | 一般 | 不设模式阉割 |
| 生成结果不满意的引导 | 提供对话迭代入口 | 好 | 沿用并强化 |
| 复杂 B 端页面堆砌 | ⚠️ 无质量预警 | 差 | 生成时加入信息层级约束 |

## 3. 与提示词增强（F-PE-01）的衔接结论

Stitch 在「步骤 3 需求输入」环节的引导设计，是本功能设计的重要参照：

| 维度 | Stitch 的做法 | 本项目的做法 | 差异价值 |
|---|---|---|---|
| 降低输入门槛 | 输入框旁给 Prompt 范例（**给答案**） | 对用户已有输入自动转化（**改作业**） | 对真实输入的适配性更强 |
| 用户控制权 | 范例可选可不选 | 默认手动触发，可跳过 | 同样尊重控制权 |
| 隐含教学 | Prompt Guide 单向阅读 | 增强结果可视对比 | 用户在对比中自然习得 |

> **结论**：Stitch 的引导是「**静态的、离线的、需要用户主动学的**」；本项目的增强是「**动态的、在线的、用户被动获得的**」。后者能覆盖前者覆盖不到的用户——那些连范例都懒得看的用户。
