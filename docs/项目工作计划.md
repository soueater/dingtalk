## 1. 项目总体架构（一句话）

> **`Design JSON` 作为唯一数据源，AI 生成 = 产出 JSON；可视化编辑 = 修改 JSON；画布渲染 / 多格式导出 = JSON 的三种消费方式。**

这个单一数据源架构是本项目的技术地基，它同时解决了三个核心难题：

- **AI 生成与编辑器解耦**：大模型只需输出结构化 JSON，不碰渲染细节，稳定性大幅提升；换模型不影响编辑器。
- **导出零损耗**：因为 Stitch 本身的产物就是 HTML/CSS，画布采用 DOM 渲染，`JSON → HTML` 几乎是模板拼装，保真度天然高。
- **编辑器可实时**：编辑操作只改 JSON 的局部节点，重渲染范围可控，避免整页重绘造成卡顿。

```
┌─────────────┐    ┌──────────────┐    ┌──────────────┐    ┌─────────────────┐
│  需求输入    │───▶│ 提示词增强器  │───▶│  LLM 生成层   │───▶│  Design JSON    │
│ (自然语言/   │    │ (F-PE-01)    │    │ (可配置模型)  │    │  (唯一数据源)    │
│  参考图)     │    │ 旁路·可跳过   │    │  Schema 校验  │    └────────┬────────┘
└─────────────┘    └──────────────┘    └──────────────┘             │
                                                                    │
                        ┌───────────────────────────────────────────┼───────────────────────────┐
                        ▼                                           ▼                           ▼
                 ┌─────────────┐                            ┌─────────────┐             ┌─────────────┐
                 │  画布渲染器  │                            │  属性编辑器  │             │  导出引擎    │
                 │ (iframe DOM)│                            │ (双向绑定)   │             │ PNG/SVG/HTML│
                 └─────────────┘                            └─────────────┘             └─────────────┘
```

> 提示词增强器为**旁路模块**：用户可跳过，跳过时直接用原始描述进入生成层。详见 `docs/功能设计-提示词增强.md`。

## 3. 各阶段详述

### S1｜产品分析阶段

**阶段目标**：以 Google Stitch 为样本，完成产品视角的全维度拆解，产出体系化分析结论，为 S2 的功能取舍提供直接依据。

**工作内容**

| 编号 | 分析维度 | 关键问题 |
|---|---|---|
| S1-1 | 产品定位与价值体系 | 目标用户画像（设计师 / PM / 独立开发者 / 学生）、核心场景、价值主张、赛道差异化（vs Figma / v0 / Bolt.new / Uizard）、能力边界与不适用场景 |
| S1-2 | 核心功能全量拆解 | 逐模块梳理：AI 原型生成（含 Variants 多变体、Canvas Flow 流程生成）、可视化编辑（Multi-Select 多屏联改、元素微调）、原生组件库、页面逻辑配置、导出与分享（HTML/Tailwind/JSX 代码、Figma、公开只读链接）；**另需增加「输入辅助 / 提示词引导能力对标」子项**，分析 Stitch 的示例提示词与输入引导机制，为本项目「提示词增强」功能（F-PE-01）确立差异化定位；每项明确**触发条件 / 输入 / 输出 / 能力上限** |
| S1-3 | 全链路交互流程还原 | 启动 → 创建项目 → 设备类型选择（Mobile/Web/Tablet/Agnostic）→ 需求输入 → AI 生成（含加载态与流式反馈）→ 多页面切换 → 元素编辑 → 属性调整 → 跳转逻辑配置 → 导出交付；逐步拆解交互反馈、操作入口、异常处理、引导逻辑 |
| S1-4 | 界面布局与信息架构 | 整体布局框架（侧栏 / 画布 / 属性区三段式）、功能区域划分、导航体系、组件排布逻辑、视觉层级与信息权重，总结底层设计逻辑 |
| S1-5 | 分析结论与落地建议 | 提炼核心设计亮点与可复用经验、现存体验痛点与优化空间，针对**本地客户端形态**给出明确的功能取舍矩阵与适配建议 |
| S1-6 | 可复用性研究 | 梳理哪些能力可 1:1 复刻、哪些需替换实现路径（如 Figma 导出 → 本地文件系统导出）、哪些属服务端能力需重新设计（如公开分享链接 → 本地静态 HTML 导出） |

**交付物清单**
1. `analysis/S1-1-产品定位与价值体系.md`
2. `analysis/S1-2-核心功能全量拆解.md`
3. `analysis/S1-3-全链路交互流程还原.md`
4. `analysis/S1-4-界面布局与信息架构.md`
5. `analysis/S1-5-结论与落地建议.md`（含**功能取舍矩阵**）
6. `analysis/S1-6-可复用性研究.md`

**前置依赖**：无
**风险**：Stitch 为 Google Labs 实验产品，功能迭代快，且需登录才可完整体验 → 应对：以官方文档 + SDK 接口清单 + 多来源实测资料交叉验证，明确标注信息可信度等级与时效性。

**工作内容**

| 编号 | 内容 | 说明 |

### S3｜开发实现阶段

拆为 5 个子阶段，每个子阶段结束同步进展并确认后进入下一子阶段。

#### S3-3A｜工程骨架 + 大模型配置面板

**目标**：客户端能启动、能配置模型、能连通测试。

工作内容：
- Electron 工程初始化（Vite + React + TypeScript），主进程 / 预加载 / 渲染进程三层搭建，安全策略（contextIsolation + IPC 白名单）配置
- 三段式主界面骨架（左侧栏 / 中央画布 / 右侧属性区），深色调设计系统落地
- **大模型配置面板**：分步引导式配置流程 → ①选择服务商预置模板 ②填写 API 地址 / 密钥 / 模型名 ③参数配置（temperature、max_tokens、超时）④**连通性测试**并实时反馈结果
- 配置加密存储于本地（Electron `safeStorage`），密钥不落明文；支持多套配置保存与一键切换

**交付物**：可启动的客户端骨架 + 可用的模型配置面板 + `docs/S3-3A-进展说明.md`
**前置依赖**：S2 确认

#### S3-3B｜AI 原型生成引擎

**目标**：自然语言 → 多页面原型 JSON → 渲染上屏。

工作内容：
- **【前置子模块】提示词增强器（F-PE-01）**：作为生成引擎的第一环，先于原型生成实现。包含输入分级判定、增强调用、结果就地覆盖与撤回、后置意图保全校验、异常降级。详见 `docs/功能设计-提示词增强.md`。之所以前置于生成，是因为它复用 LLM 适配层但不依赖生成逻辑，可独立开发与验证。
- 多厂商 API 适配层（统一 `chat()` 接口，抹平 OpenAI / Anthropic / Gemini / Ollama 差异）
- **Prompt 编排流水线**：需求理解 → 信息架构规划（决定生成哪几个页面）→ 逐页生成 Design JSON → 设计 Token 一致性约束
- **结构化输出与容错**：JSON Schema 校验 + 自动修复重试（解析失败 / 字段缺失 / 越界值均走修复链路，最多 N 次）
- 生成过程流式反馈：逐页出现 + 骨架屏 + 进度提示
- 生成结果落盘为项目文件（`.dsproj`），支持项目列表与历史项目打开

**交付物**：可用的 AI 生成功能（含提示词增强器 F-PE-01）+ `docs/S3-3B-进展说明.md`
**前置依赖**：S3-3A；**外部依赖：用户提供可用的大模型 API**

#### S3-3C｜可视化编辑器内核

**目标**：拖拽、增删改、属性调整全部实时生效。

工作内容：
- 画布渲染器：`Design JSON → DOM` 递归渲染，iframe 隔离保证样式不泄漏
- **选择系统**：点选 / 框选 / Shift 多选 / 图层树联动高亮
- **拖拽系统**：基于 Pointer Events 自研，支持移动 / 8 向缩放 / 吸附对齐 / 智能参考线 / 键盘微调（方向键 + Shift 加速）
- **属性面板**：位置尺寸、布局（Flex / 绝对定位）、间距、字体排版、颜色、圆角、边框、阴影、透明度；改动即时双向同步
- **组件库面板**：内置常用组件，拖入画布即实例化
- **操作历史**：完整 Undo / Redo（基于 JSON 快照 + 增量 patch），支持 Ctrl+Z / Ctrl+Shift+Z
- 图层面板：树形结构、重命名、显隐、锁定、层级调整

**交付物**：可完整编辑的编辑器 + `docs/S3-3C-进展说明.md`
**前置依赖**：S3-3A（架构）/ S3-3B（有真实数据可编辑）
**风险**：拖拽性能是本阶段最大风险 → 应对：位移仅走 CSS `transform` 不触发布局重排；参考线计算做节流；大图层树做虚拟滚动。目标：60fps 无掉帧。

#### S3-3D｜多页面管理 + 页面跳转逻辑

**目标**：还原 Stitch 的 Canvas Flow 与多屏协作能力。

工作内容：
- 多页面管理：新建 / 复制 / 删除 / 排序 / 重命名，页面缩略图导航
- **画布流视图**：页面以流程图形式排布，可拖拽调整位置，连线展示跳转关系
- **跳转逻辑配置**：选中元素 → 绑定目标页面 / 触发方式（点击 / 悬停）；生成可交互的原型预览模式
- **多屏批量编辑**：框选多个页面 → 一次指令批量应用修改（对标 Stitch Multi-Select）
- **变体生成（Variants）**：对同一页面生成多个设计变体供对比选用

**交付物**：多页面 + 跳转逻辑 + 变体功能 + `docs/S3-3D-进展说明.md`
**前置依赖**：S3-3C

#### S3-3E｜导出引擎 + 打包分发

**目标**：多格式导出可用，程序双击即启动。

工作内容：
- **PNG 导出**：支持单页 / 全部页面 / 2x 高清，可配背景透明
- **SVG 导出**：矢量保真，文本保持可编辑
- **HTML 导出**：单文件自包含（样式内联 + 资源内联），含页面跳转、可直接浏览器打开预览；另提供多文件工程版（HTML + CSS 分离）便于前端二次开发
- 可选附加：JSON 源文件导出（便于版本管理与二次编辑）
- **打包分发**：`electron-builder` 产出 ①免安装绿色版（双击即用，满足「无需部署、双击启动」要求）②标准安装包
- 应用图标、启动画面、关于页

**交付物**：多格式导出功能 + Windows 免安装绿色版 + `docs/S3-3E-进展说明.md`
**前置依赖**：S3-3C / S3-3D
**风险**：导出保真度（字体 / 阴影 / 滤镜支持度差异）→ 应对：导出前做样式归一化；PNG 导出走真实渲染快照而非重绘，保证所见即所得。

### S4｜测试验收阶段

**阶段目标**：确认交付物可用、稳定、可交付。

工作内容：
- **功能测试**：四大核心链路（生成 / 编辑 / 跳转 / 导出）逐项验收；覆盖异常分支（网络失败、密钥错误、模型返回异常、超大图层数）
- **性能测试**：冷启动耗时、生成响应耗时、拖拽帧率、100+ 页面项目加载耗时
- **兼容性测试**：多分辨率 / 深色浅色 / 不同厂商模型接入
- **配置健壮性**：错误密钥、错误地址、超时、模型名不存在等场景的引导与提示
- **提示词增强专项测试（F-PE-01）**：L0-L3 四级输入全覆盖、意图保全校验有效性、异常降级路径、幂等性（反复增强不膨胀）、跨模型一致性
- **打包产物验证**：在干净环境下解压启动，确认无缺失依赖
- 文档撰写

**交付物清单**
1. `docs/测试报告.md`
2. `docs/大模型配置操作指南.md`
3. `docs/产品使用说明文档.md`
4. Windows 免安装绿色版压缩包（最终交付程序）

**前置依赖**：S3 全部子阶段完成

## 5. 风险登记册

| 编号 | 风险 | 等级 | 应对预案 |
|---|---|---|---|
| R1 | LLM 输出 JSON 格式不稳定，导致解析失败 | 高 | Schema 强校验 + 自动修复重试 + 降级为宽松解析；Prompt 中内嵌 Schema 约束与少样本示例 |
| R2 | 拖拽 / 大量图层渲染卡顿，达不到「无明显延迟」要求 | 高 | transform 位移、计算节流、虚拟滚动、局部重渲染；S3-3C 设专项性能验收门槛 |
| R3 | Schema 设计缺陷导致后期重构 | 中 | S2 先用示例数据验证渲染可行性再冻结；编辑器与导出器均只依赖 Schema 不依赖内部实现 |
| R4 | 导出保真度不足（字体 / 阴影 / 图片） | 中 | 样式归一化 + 资源内联 + PNG 走真实渲染快照 |
| R5 | 不同厂商模型接口差异大，适配不全 | 中 | 适配层抽象统一接口；优先保证 OpenAI 兼容协议（覆盖最广），其余逐步补充 |
| R6 | 用户无可用 API Key，无法验证生成效果 | 中 | 内置 Mock 模式与示例项目，保证无密钥也能完整走通编辑/导出链路 |
