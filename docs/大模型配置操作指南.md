> 适用版本：望舒 v1.1

## 1. 配置总览

### 入口位置

| 方式 | 操作 |
|---|---|
| 顶栏 | 点击右上角显示模型名称的按钮 |
| 菜单 | 按 `Ctrl + ,` |
| 提示触发 | 未配置时点击「生成」，会提示并自动打开配置面板 |

### 界面结构

配置面板分为左右两栏：

- **左栏**：已保存的配置列表。可新建、删除、设为默认。支持保存多套配置随时切换。
- **右栏**：当前配置的详细表单，顶部有三步引导条，底部为「测试连接」与「保存」。

### 配置项的四个必填项

| 字段 | 说明 | 示例 |
|---|---|---|
| **配置名称** | 仅用于你自己辨识 | 我的 GPT-4o |
| **服务商类型** | 决定请求格式与鉴权方式 | OpenAI 兼容 |
| **接口地址** | 模型服务的 API 根地址 | `https://api.openai.com/v1` |
| **模型名称** | 具体调用哪个模型 | `gpt-4o-mini` |

密钥是否必填取决于服务商：云端服务必填，本地 Ollama 不需要。

## 2. 分步引导（四步完成）

### 第一步：选择服务商类型

点击「服务商类型」下拉框，四个选项对应四套不同的请求协议：

| 类型 | 适用场景 |
|---|---|
| **OpenAI 兼容** | 绝大多数服务。包括 OpenAI 官方、DeepSeek、Moonshot、通义千问、智谱、硅基流动、本地 vLLM、One-API 等 |
| **Anthropic Claude** | Anthropic 官方 Claude 系列 |
| **Google Gemini** | Google AI Studio 的 Gemini 系列 |
| **Ollama（本地）** | 本机运行的 Ollama，完全离线 |

选中后，接口地址与模型名会自动填入该服务商的推荐默认值，通常无需修改。

> **提示**：90% 的情况选「OpenAI 兼容」即可。它是一套事实标准，几乎所有服务商都提供兼容端点。

### 第二步：填写接口地址

接口地址（Base URL）是模型服务的入口。**最常见的配置错误就是这里**。

判断标准：**该地址拼接 `/chat/completions` 后应当能访问**（Anthropic 与 Gemini 除外，它们路径不同）。

正确示例：
```
https://api.openai.com/v1
https://api.deepseek.com/v1
http://127.0.0.1:11434/v1
```

错误示例：
```
https://api.openai.com              ← 缺少 /v1
https://api.openai.com/v1/chat/completions   ← 多了路径，会重复拼接
https://api.openai.com/v1/          ← 末尾斜杠（程序会自动清理，但不建议）
```

选「OpenAI 兼容」时，地址下方会出现一排快捷按钮（OpenAI / DeepSeek / Moonshot / 通义千问 / 智谱 / 硅基流动 / 本地 Ollama），点击即可一键填入。

### 第三步：填写模型名称与密钥

**模型名称**需与该服务商的实际模型 ID 完全一致，区分大小写。输入框支持下拉提示（该服务商的常用模型）。

**API 密钥**获取方式：

1. 登录对应服务商的控制台
2. 找到 API Keys / 密钥管理页面
3. 创建新密钥并复制（通常只显示一次，请及时保存）

密钥输入框右侧有眼睛图标可切换明文显示，便于核对。

### 第四步：测试连接并保存

点击 **「测试连接」**。程序会发送一个最小请求验证链路：

- **成功**：绿色提示，显示往返延迟（如 `连接成功 · 842 ms · gpt-4o-mini`）
- **失败**：红色提示，附带错误码（见 [第 8 节](#8-故障排查对照表)）

测试通过后点击 **「保存」**。若这是第一套配置，会自动设为默认。

## 3. 四类服务商完整配置说明

### 3.1 OpenAI 兼容（推荐）

| 项 | 值 |
|---|---|
| 接口地址 | `https://api.openai.com/v1` |
| 模型示例 | `gpt-4o-mini`、`gpt-4o`、`gpt-4.1` |
| 密钥前缀 | `sk-` |
| 密钥获取 | https://platform.openai.com/api-keys |

请求协议为 `POST /v1/chat/completions`，鉴权头 `Authorization: Bearer <key>`。

**该类型是万能的**：任何提供 OpenAI 兼容端点的服务都可以用它接入，只需改地址、模型名和密钥。

### 3.2 Anthropic Claude

| 项 | 值 |
|---|---|
| 接口地址 | `https://api.anthropic.com` |
| 模型示例 | `claude-sonnet-4-5`、`claude-opus-4-1` |
| 密钥前缀 | `sk-ant-` |
| 密钥获取 | https://console.anthropic.com/settings/keys |

**注意**：接口地址**不要**加 `/v1`。程序使用 `/v1/messages` 协议，会自动补全路径并附加 `anthropic-version` 请求头。

Claude 在长结构化输出上表现稳定，适合生成结构复杂的多页设计。

### 3.3 Google Gemini

| 项 | 值 |
|---|---|
| 接口地址 | `https://generativelanguage.googleapis.com/v1beta` |
| 模型示例 | `gemini-2.5-flash`、`gemini-2.5-pro` |
| 密钥前缀 | `AIza` |
| 密钥获取 | https://aistudio.google.com/app/apikey |

**注意**：地址已含 `/v1beta`，请勿重复添加。鉴权通过 URL 参数 `?key=` 传递。

`gemini-2.5-flash` 速度最快、成本低，适合日常生成。

### 3.4 Ollama（本地）

| 项 | 值 |
|---|---|
| 接口地址 | `http://127.0.0.1:11434` |
| 模型示例 | `qwen2.5:14b`、`llama3.1:8b` |
| 密钥 | **不需要**，留空 |

使用前需在本机完成：

```bash
# 1. 安装 Ollama（访问 ollama.com 下载）
# 2. 拉取模型
ollama pull qwen2.5:14b
# 3. 确认服务运行（默认监听 11434）
ollama list
```

**能力提示**：建议使用 14B 及以上参数量的模型。7B 以下模型在生成长结构化 JSON 时容易格式出错（程序有容错兜底，但失败率会上升）。首次调用需要加载模型到内存，可能等待数十秒，属正常现象。

## 5. 完全本地运行（Ollama）

若对数据隐私有严格要求，可全程离线：

1. 安装 Ollama 并拉取模型
2. 配置面板选「Ollama（本地）」
3. 地址保持 `http://127.0.0.1:11434`
4. 密钥留空
5. 测试连接

**此时从描述生成界面、提示词增强等全部能力都在本机完成，不会有任何数据离开你的电脑。**

推荐模型（按生成质量排序）：

| 模型 | 参数量 | 说明 |
|---|---|---|
| `qwen2.5:14b` | 14B | 综合最佳，中文与结构化输出都稳定 |
| `qwen2.5-coder:14b` | 14B | 代码与结构化输出强 |
| `deepseek-coder-v2` | 16B | 结构化输出优秀 |
| `llama3.1:8b` | 8B | 体积小、速度快，格式稳定性一般 |

内存需求参考：8B 约需 8GB，14B 约需 16GB，32B 约需 32GB。

## 6. 参数调优建议

点开表单底部的「高级参数」展开。

### 温度（Temperature）

控制输出的随机性。程序内部已针对不同任务自动采用不同温度：

| 任务 | 内部温度 | 说明 |
|---|---|---|
| 提示词增强 | 0.25 | 低温度保证忠实复述意图 |
| 信息架构规划 | 0.4 | 结构化规划，稳定优先 |
| 设计规范定稿 | 0.3 | 规范化输出 |
| 页面生成 | 0.6 | 兼顾创造性与稳定性 |
| 对话式编辑 | 0.2 | 精确改稿，不误改其他内容 |
| 生成变体 | 0.85 | 高温度产出差异化方案 |
| 格式修复 | 0.1 | 只修格式不改语义 |

表单里的温度值作为**默认基线**，上述任务是围绕它做偏移的。

### 最大输出 tokens

生成完整页面需要较长输出。**建议不低于 8192**。若设置过小，模型输出会被截断（程序有截断补救机制，但会损失部分内容）。

| 场景 | 建议值 |
|---|---|
| 单页生成 | 8192 |
| 多页项目 | 12288 ~ 16384 |
| 生成变体 | 16384 |
| 仅提示词增强 | 3072 足够 |

### 超时

默认 120 秒。使用本地模型或网络较慢时建议调高至 300 秒。

### 流式输出

建议保持开启。开启后可看到内容逐步生成，长任务时能明确知道程序在工作。

## 7. 密钥安全说明

这一点很重要，请完整阅读。

### 密钥存储位置与方式

- 密钥**只保存在你的本机**，路径为应用数据目录下的加密文件
- 优先使用操作系统提供的加密能力（Windows DPAPI / macOS Keychain 加密后再落盘）
- 若当前系统不支持，则降级为混淆存储，界面会明确标注「密钥以混淆方式存储」

### 密钥不会去哪里

- ❌ 不上传到任何服务器
- ❌ 不写入项目文件（`.dsproj` 里只有设计数据）
- ❌ 不进入渲染进程内存（渲染层只持有掩码，如 `sk-****a1b2`）
- ❌ 不写入日志文件

### 请求路径

所有模型请求由主进程发出，沿以下路径：

```
渲染层（只有 configId）
  → 主进程取出密钥
  → 直接请求模型服务商
```

密钥只在主进程内短暂出现，请求完成即释放。

### 建议

- 为测试用途单独创建一个密钥，设置较低额度
- 定期在服务商控制台轮换密钥
- 不要把配置面板截图分享给别人（掩码仍会暴露部分字符）

## 8. 故障排查对照表

程序会把错误归类为 12 种错误码，逐一对应处理建议：

| 错误码 | 界面提示 | 原因 | 解决方式 |
|---|---|---|---|
| `E_AUTH` | 认证失败 | 密钥错误、失效、或额度不足 | 重新复制密钥；检查服务商账户余额 |
| `E_MODEL` | 模型不存在 | 模型名拼写错误或无权访问 | 核对模型 ID；确认账户已开通该模型 |
| `E_RATE_LIMIT` | 请求过于频繁 | 触发了服务商限流 | 等待 1 分钟后重试；或降低生成页数 |
| `E_TIMEOUT` | 请求超时 | 网络慢、模型负载高、或本地模型未加载完 | 调高超时；本地模型首次调用请耐心等待 |
| `E_NET` | 网络错误 | 地址错误、断网、或需要代理 | 检查接口地址；确认能访问外网 |
| `E_PARSE` | 输出格式异常 | 模型未按要求输出 JSON | 换用能力更强的模型；或降低温度 |
| `E_SCHEMA` | 结构不符合规范 | 输出 JSON 结构不完整 | 程序已自动修补；若持续出现请更换模型 |
| `E_FS_PERM` | 无权限 | 目标目录不可写 | 换一个保存位置（如文档目录） |
| `E_FS_NOTFOUND` | 文件不存在 | 项目文件被移动或删除 | 从最近项目列表移除该条目 |
| `E_FS_CORRUPT` | 文件已损坏 | 项目文件被破坏 | 从备份恢复；或使用设计源文件 `design.json` |
| `E_ABORTED` | 已取消 | 你主动中断了生成 | 无需处理 |
| `E_UNKNOWN` | 未知错误 | 兜底 | 查看应用数据目录下的 `error.log` |

### 快速自检清单

测试连接失败时，按顺序确认：

1. **接口地址是否完整**（含 `/v1` 或对应的版本路径）
2. **密钥是否有多余空格**（复制时常带上首尾空格）
3. **模型名是否与服务商文档一致**（区分大小写）
4. **账户是否有可用额度**
5. **本机网络能否访问该服务**（部分海外服务需要代理）
6. **本地模型服务是否在运行**（Ollama 场景执行 `ollama list` 验证）

### 网络代理情形

程序使用系统代理设置。若你的代理需要额外配置，请先确认系统级代理可用（例如在终端执行 `curl https://api.openai.com/v1/models` 验证）。
