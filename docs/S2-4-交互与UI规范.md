## 1. 布局规范

### 1.1 主界面三段式

对标 Stitch V2 形态（S1-4 §2 基线），不做无限画布。

```
┌──────────────────────────────────────────────────────────────────────────┐
│ ① 顶栏 TopBar  48px                                                        │
│ [Logo] [项目名 ▾]        [生成] [预览] [导出 ▾]      [模型: XXX ▾] [⚙] [◐] │
├────────────┬────────────────────────────────────────────┬────────────────┤
│ ② 左栏      │ ③ 中央画布区                                 │ ④ 右栏          │
│ 248px      │ flex                                        │ 296px          │
│            │                                             │                │
│ ┌────────┐ │  ┌─ 视图切换: [设计][流视图] ─────────────┐  │ ┌────────────┐ │
│ │页面标签 │ │  │                                        │  │ │[属性][组件] │ │
│ │图层标签 │ │  │        设备画框（iframe）               │  │ ├────────────┤ │
│ └────────┘ │  │        + 选区/参考线/手柄叠加层          │  │ │            │ │
│            │  │                                        │  │ │  按选区渲染 │ │
│ 页面列表    │  │                                        │  │ │  或组件列表 │ │
│ 或图层树    │  └────────────────────────────────────────┘  │ │            │ │
│            │                                             │ │            │ │
│            │  ┌─ 底部输入区（对话）───────────────────┐   │ │            │ │
│            │  │ [✨增强] 输入需求…            [发送] │   │ └────────────┘ │
│            │  └──────────────────────────────────────┘   │                │
├────────────┴────────────────────────────────────────────┴────────────────┤
│ ⑤ 状态栏 StatusBar 28px  [设备: Mobile 390×844] [缩放 100%] [节点 12] [保存✓]│
└──────────────────────────────────────────────────────────────────────────┘
```

### 1.2 尺寸常量

| 区域 | 尺寸 | 可调 | 折叠 |
|---|---|---|---|
| 顶栏 | 48px | 否 | 否 |
| 左栏 | 264px | 拖拽 200–400px | ✅ 可折叠至 0 |
| 右栏 | 300px | 拖拽 240–440px | ✅ 可折叠至 0 |
| 状态栏 | 28px | 否 | 否 |
| 画布输入区 | 最小 88px，自增高至 200px | 自动 | 可折叠 |
| iframe 画框 | 按设备尺寸 | 缩放 10%–400% | — |

> 左栏之所以是 264px 而非更窄：四个页签（AI 生成 / 页面 / 图层 / 组件）需保证**单行显示不折行**，
> 264px 是实测的最小安全宽度。

### 1.3 功能区域职责

| 区域 | 职责 | 不做什么 |
|---|---|---|
| ① 顶栏 | 全局动作（生成/预览/导出）、当前模型状态、设置入口 | 不做元素级操作 |
| ② 左栏 | 页面与图层的**结构与导航** | 不做样式编辑 |
| ③ 画布 | 所见即所得设计稿 + 直接操作 | 不显示长表单 |
| ④ 右栏 | 选中对象的**精确属性**、组件库 | 不放全局动作 |
| ⑤ 状态栏 | 只读状态反馈 | 不放任何按钮（除保存指示） |

**信息架构原则**（承接 S1-4）：
- **动作就近原则**（H-6）：元素相关操作紧贴元素（浮动词条），不集中到顶栏。
- **结构左、属性右**：符合「先找到，再调整」的认知顺序。
- **扁平二级导航**：不做三级菜单，顶栏 `导出 ▾` 与 `模型 ▾` 为最深的二级。

## 2. 核心交互流程

### 2.1 首次启动（对应 L-1 零摩擦启动）

```
双击启动
  → 显示启动画面（Logo + 加载条，≤1.5s）
  → 直接进入「项目列表页」（非登录页，无登录墙）
  → 若上次有未完成项目 → 顶部横幅「继续上次编辑」一键回到
  → 若从未配置模型 → 项目列表页顶部提示条「尚未配置大模型，点击配置」+
     仍提供「打开示例项目」入口（Mock 模式，无配置也能体验）
```

### 2.2 主流程：需求 → 生成 → 编辑 → 导出

```
① 新建/打开项目
      │
② 底部输入需求（可选点「✨增强」优化提示词）
      │
③ 点「生成」→ 顶栏进度 + 画布骨架屏
      │    （逐页出现，页面先在流视图占位再填充）
④ 生成完成 → 自动切到「设计」视图 + 选中首页
      │
⑤ 编辑（三通道任一）
      ├─ 对话：底部输入「把按钮改成圆角」→ 生成 patch → 应用
      ├─ 拖拽：选中元素 → 拖动 → 吸附对齐 → 松手提交
      └─ 面板：右栏改属性 → 即时生效
      │
⑥ 切「流视图」→ 拖拽排布页面 + 连线配置跳转
      │
⑦ 点「预览」→ 进入交互预览模式，真实点击跳转
      │
⑧ 点「导出 ▾」→ 选格式 → 选路径 → 完成
```

### 2.3 交互设计七规律落地（承接 S1-3）

| 规律 | 在本项目的落地 |
|---|---|
| **L-1 零摩擦启动** | 无登录、启动直达项目列表、示例项目一键进入 |
| **L-2 选择优于重试** | 变体生成：一次给 3 个方案平铺对比，而非失败后重试 |
| **L-3 就近动作** | 选中元素 → 浮动工具条（复制/删除/编组/上移下移）+ 右栏联动 |
| **L-4 全局优先** | Token 面板改一次全局生效；多选批量改 |
| **L-5 渐进披露** | 属性面板「基础」默认展开，「状态/高级」折叠；高级 CSS 折叠 |
| **L-6 即时反馈** | 所有编辑 <16ms 上屏；生成有逐页进度；保存有状态指示 |
| **L-7 导出即交付** | 导出是一等公民，顶栏常驻；导出前有格式说明与预览 |

## 3. 三通道编辑交互

### 3.1 通道 A：对话编辑

| 项 | 规范 |
|---|---|
| 入口 | 画布底部常驻输入框 |
| 输入 | 自然语言，支持「选择上下文」——若当前有选中元素，默认作用于该元素 |
| 上下文指示 | 输入框上方显示 chip：`作用于：登录按钮`（可点 × 取消，回到全页） |
| 处理 | LLM → JSON Patch → 校验 → 应用为**一笔历史事务** |
| 反馈 | 输入框上方显示「已应用：3 处变更」+「撤销」快捷按钮 |
| 失败 | 显示「未能识别修改意图，请更具体描述」+ 原文重编辑 |
| 与增强器关系 | 编辑类输入**不走**增强器（增强器针对「生成新页面」的长描述） |

### 3.2 通道 B：拖拽编辑

| 操作 | 交互 |
|---|---|
| 选中 | 单击选中；Shift+单击加选；画布空白拖拽框选；左栏图层树点击联动 |
| 移动 | 拖元素本体；按住 Space 或选中后方向键微调（1px，Shift 加速 10px） |
| 缩放 | 选中后 8 个手柄；角手柄等比（Shift 锁定比例）；边手柄单轴 |
| 吸附 | 默认开启。临近父容器边距/兄弟元素边缘/画布中线时吸附，显示粉色吸附线 |
| 参考线 | 与兄弟元素对齐时显示蓝色参考线；显示实时距离标签 |
| 跨容器 | 拖到其他容器上时高亮目标容器，松手后重新计算坐标系 |
| 幽灵层 | 拖动中只移动半透明占位框，松手才提交真实 patch（保证 60fps） |
| 约束提示 | 若目标父容器为 flex，拖动只改变顺序而非自由坐标 → 显示提示 |

### 3.3 通道 C：属性面板编辑

| 项 | 规范 |
|---|---|
| 绑定 | 单向：面板读 JSON；改动写 JSON（经 applyPatch） |
| 多选 | 多选时展示「共有属性」；改动应用到全部选中项；不一致的属性显示「混合值」 |
| 输入 | 数字输入支持：拖拽调节、方向键增减、回车提交、Esc 取消 |
| Token 优先 | 颜色字段默认吸 Token，可切「自定义」 |
| 实时性 | 输入过程中即时预览（不待回车），回车确认入历史 |

## 5. 状态设计

### 5.1 空态

| 场景 | 设计 |
|---|---|
| 项目列表空 | 居中插画 + 「新建第一个项目」+ 「打开示例项目」双按钮 |
| 画布无页面 | 显示示例提示词卡片（3 条可点击填入）+ 「或打开示例项目」 |
| 图层树空 | 弱化文案「当前页面暂无图层」 |
| 组件搜索结果空 | 「未找到匹配组件」+ 建议关键词 |
| 未配置模型 | 输入框上方黄色提示条「未配置大模型，将使用示例数据模式」+「去配置」 |

### 5.2 加载态

| 场景 | 设计 |
|---|---|
| 应用启动 | 启动画面：Logo + 进度条（>1.5s 显示） |
| 项目打开 | 画布区骨架屏（模拟布局色块） |
| **AI 生成** | ① 顶栏进度环 + 阶段文字「理解需求 → 规划页面 → 生成页面 2/4」；② 画布区逐页出现骨架屏，完成一页替换一页；③ 流视图同步出现页面占位节点；④ 可随时「停止」 |
| 提示词增强 | 输入框旁 spinner + 「正在优化描述…」；输出区先显示骨架行 |
| 导出 | 模态内进度条 + 当前阶段文字 |
| 保存 | 状态栏「保存中…」→「已保存 ✓」 |

### 5.3 错误态

错误码到 UI 文案与引导的映射（对应 S2-1 §3.2）：

| 错误码 | 用户可见文案 | 引导动作 |
|---|---|---|
| `E_NET` | 无法连接到模型服务，请检查网络与服务地址 | [检查配置] [重试] |
| `E_AUTH` | 密钥无效或已过期 | [打开配置] |
| `E_TIMEOUT` | 请求超时（已等待 60s） | [重试] [调大超时设置] |
| `E_RATE_LIMIT` | 触发服务方限流，请稍后再试 | [等待重试] |
| `E_MODEL` | 模型名不存在或当前密钥无权访问 | [打开配置] [查看常见模型名] |
| `E_PARSE` | 模型返回内容无法解析 | [重试] [换用更强模型] |
| `E_SCHEMA` | 生成结构与预期不符（已尝试自动修复 2 次） | [重试] [用更具体的描述] [查看原始返回] |
| `E_FS_PERM` | 无权限写入该位置 | [另选位置] |
| `E_FS_CORRUPT` | 项目文件已损坏 | [尝试恢复] [从备份打开] |
| `E_ABORTED` | 已取消 | — |

**错误展示规范**：
- 轻错误（可自动恢复）：Toast，3 秒消失
- 中错误（需用户动作）：内联错误条，带引导按钮，不阻塞
- 重错误（阻塞链路）：模态对话框，必须处理才能继续

### 5.4 选中态 / 悬停态

| 状态 | 视觉 |
|---|---|
| 悬停（画布元素） | 1px `--app-accent` 蓝色描边（半透明） |
| 选中 | 2px `--app-accent` 实线 + 8 个白色方块手柄 |
| 多选 | 所有选中元素描边 + 整体包围框 |
| 悬停（图层树行） | 背景 `--app-hover` |

| 隐藏元素 | 图层树行 40% 透明度 + 眼睛图标划线 |

## 6. 反馈与微交互规范

| 交互 | 反馈 | 时长 |
|---|---|---|
| 按钮悬停 | 背景色变亮（`--app-accent` → `--app-accent-hover`） | 120ms ease |
| 按钮按下 | 缩放 0.98 | 80ms |
| 面板折叠 | 宽度动画 | 200ms ease-out |
| 浮层出现 | 淡入 + 上移 4px | 160ms ease-out |
| 模态出现 | 背景遮罩淡入 + 卡片缩放 0.96→1 | 180ms |
| Toast 出现 | 从顶部滑入 | 220ms spring |
| 属性变更生效 | 元素高亮闪烁一次（浅蓝） | 300ms |
| 保存成功 | 状态栏图标变绿 + 对勾 | 瞬时 |
| 拖拽吸附 | 吸附线闪现 + 轻微震动感（视觉抖动 2px） | 100ms |
| 生成完成 | 画布区轻闪 + 状态栏提示「生成 4 个页面」 | 400ms |

**动效原则**：
- 所有动画 ≤250ms，避免拖慢操作节奏。
- 尊重 `prefers-reduced-motion`，开启时取消位移类动画，只保留淡入淡出。
- 不做装饰性动画（不用动画炫技），每处动效都必须传达「发生了什么」。

## 7. 视觉层级与信息权重

### 7.1 层级手法

| 手段 | 用法 |
|---|---|
| 明度层级 | 底 `--app-bg` → 面板 `--surface-1` → 浮层 `--surface-3`，越靠前越亮（浅色主题反向收敛，靠阴影补足） |
| 边框权重 | 主分隔 `--border`，强调分隔 `--border-strong`，弱分隔用背景差 |
| 文字权重 | 主 `--text-1` / 次 `--text-2` / 弱 `--text-3`，三级够用 |
| 强调色克制 | 全界面只有 `--brand` 一种强调色；语义色（成功/警告/危险）仅用于真实状态 |
| 留白 | 面板内边距统一 12px，区块间距 16px，不做紧凑到窒息的专业工具风 |
| chrome 区分 | 顶栏用 `surface-2 → surface-1` 微渐变、状态栏用更暗的 `--app-bg`，与内容区拉开层次 |

### 7.2 编辑器 vs 预览的模式区分

| 模式 | 区分手法 |
|---|---|
| 编辑模式 | 顶栏显示编辑工具组；画布有选区/参考线；右栏展开 |
| 预览模式 | 顶栏简化为「返回编辑」+ 设备切换；隐藏所有编辑浮层；画布加暗背景突出设备；支持真实点击跳转 |

### 7.3 外观主题

工具外壳提供 **4 套内置主题**，定义见 S2-3 §5.1。规范要求：

- 切换入口固定在顶栏右侧（调色盘图标），位置不随版本变化
- 切换**即时生效**：不重启、不重载、不丢未保存状态，并写入 localStorage 记忆
- 新增样式**禁止硬编码颜色**，否则浅色主题下会出现"深色孤岛"
- 主题只影响工具外壳，**绝不改变设计稿与导出产物**

## 8. 响应式与适配

| 场景 | 策略 |
|---|---|
| 窗口宽度 < 1180px | 右栏自动折叠为图标条 |
| 窗口宽度 < 900px | 左栏也折叠；显示提示「建议窗口宽度 ≥1280px」 |
| 高 DPI | 全部尺寸使用逻辑像素；图标提供 2x 资源 |
| 深浅主题 | **v1.0 已提供 4 套主题**（夜阑 / 晨光 / 沧海 / 墨韵），即时切换并持久化；默认夜阑（深色） |
| 设计稿深浅 | 与工具主题无关——设计稿配色由项目 Token 决定，在 iframe 内独立呈现 |

## 10. 应用图标规范

图标要同时被三种阅读距离使用：**16px**（任务栏 / 文件列表 / 标题栏）、**32–48px**（桌面 / 开始菜单）、**256–1024px**（安装器 / 关于页 / 商店）。手改某一张 PNG 无法保证「各尺寸看起来是同一个东西」，因此几何全部按**归一化坐标**定义，再由脚本按目标尺寸重新光栅化。

### 10.1 构成与含义

| 层 | 规范 | 含义 |
|---|---|---|
| 底板 | 圆角矩形，`radius / 边长 = 0.2229`（≈ macOS squircle 观感） | 夜色的画板 |
| 底色 | 对角线性渐变 `#7FB2FF → #4C8DFF(48%) → #8858F6` | 与 `tokens.css` 的 `--brand` / `--brand-2` 同源 |
| 柔光 | 左上径向柔光，峰值 alpha `0.30` | 体积感 |
| 主体 | 新月 = 外圆 `(0.478, 0.512, r 0.238)` 挖去偏移内圆 `(0.606, 0.418, r 0.208)`；近白而非纯白 | 望舒为月御 |
| 点睛 | 四角星芒，中心 `(0.706, 0.322)`，`r 0.065`，腰部收敛比 `0.17` | 灵感 |

### 10.2 尺寸分档（关键：小尺寸必须单独一档）

同一份几何直接缩到 16px 会退化成「白团压白底」——柔光正好落在月亮所在区域，把底色提亮到 `#7FB2FF`，白月对比度掉到约 **2.4:1**。因此按档位调整**装饰强度**，而不是缩放主体：

| 档位 | 尺寸 | 柔光 | 星芒 |
|---|---|---|---|
| 精简档 | 16 / 24 | 关闭（0） | 不绘制（放大后仍不足 2px，只会糊成脏点） |
| 收敛档 | 32 / 48 | 减半（0.16） | 放大到 `r 0.086` 以补回被缩掉的视觉重量 |
| 标准档 | ≥ 64 | 0.30 | `r 0.065` |

调整后 16px 下底色回到 `#4C8DFF` 一带，白月对比度约 **4.3:1**，新月开口可辨。

### 10.3 产物与再生成

| 产物 | 用途 |
|---|---|
| `build/icon.png`（1024） | `build.win.icon` / 窗口图标主图 |
| `build/icon.ico` | 内嵌 16/24/32/48/64/128/256 七档位图，供 exe / 安装器 / 卸载器 |
| `build/icons/<n>x<n>.png` | 各尺寸独立 PNG（Linux、文档、关于页） |
| `build/icon.svg` | 设计源（**标准档**几何，人工可编辑） |
| `public/favicon.png`（64） | 渲染层页面图标；打包后另经 `extraResources` 落到 `resources/icon.png` |

再生成：`npm run icons`（需 Pillow）。改几何时**脚本与 `icon.svg` 必须同步**，否则两者会分叉。

### 10.4 图标核验（可直接判定）

「生成对了」和「exe 里真的是它」是两件事：`win.icon` 路径写错或 rcedit 失败时，构建日志依然全绿，但 exe 用的是 Electron 默认图标 —— 属于纯静默失败。因此提供一条机器可判定的核验：

```bash
npm run icons:verify          # 等价于 python scripts/verify-exe-icons.py out/artifacts
```

它直接解析 PE 资源目录，断言每个 exe 都带 `RT_GROUP_ICON` 且 `RT_ICON` 覆盖 `16/24/32/48/64/128/256` 全部档位。当前实测：

| 产物 | 结果 |
|---|---|
| `out/artifacts/win-unpacked/望舒.exe` | `RT_GROUP_ICON=1 RT_ICON=7` 尺寸齐全 |
| `out/artifacts/望舒 Setup 1.1.0.exe` | 同上 |
| `out/artifacts/望舒-1.1.0-portable.exe` | 同上 |

> 运行时取图标的唯一入口是 `electron/main/window-manager.ts` 的 `resolveIconPath()`：打包态读 `process.resourcesPath/icon.png`（依赖 `build.extraResources`），开发态读 `app.getAppPath()/build/icon.png`。
