## 1. 架构总览

### 1.1 一句话架构

> **Design JSON 是唯一数据源；主进程管「能不能跑」，渲染进程管「长什么样」，预加载层管「两者怎么说话」。**

### 1.2 分层视图

```
┌──────────────────────────────────────────────────────────────────────┐
│                          RENDERER PROCESS (UI)                        │
│  ┌────────────┐ ┌────────────┐ ┌────────────┐ ┌────────────────────┐ │
│  │ 左栏        │ │ 中央画布    │ │ 右栏        │ │ 顶层浮层            │ │
│  │ 页面/图层   │ │ 渲染器+选区 │ │ 属性/组件   │ │ 配置/增强/导出/预览  │ │
│  └────────────┘ └────────────┘ └────────────┘ └────────────────────┘ │
│  ─────────────────── 应用状态层 (Zustand) ───────────────────         │
│   ProjectStore │ EditorStore │ ConfigStore │ HistoryStore │ UIStore   │
│  ─────────────────── 领域服务层 ───────────────────                    │
│   Renderer │ SelectionEngine │ DragEngine │ ExportEngine │ LlmClient   │
└───────────────────────────────┬──────────────────────────────────────┘
                                │  contextBridge (白名单 API)
┌───────────────────────────────▼──────────────────────────────────────┐
│                          PRELOAD (Bridge)                             │
│   window.api = { fs, dialog, config, secureStore, app, shell }        │
│   只暴露语义化方法，不暴露 ipcRenderer 原始对象                        │
└───────────────────────────────┬──────────────────────────────────────┘
                                │  ipcMain.handle (invoke/handle)
┌───────────────────────────────▼──────────────────────────────────────┐
│                         MAIN PROCESS (Node)                           │
│   窗口生命周期 │ 项目文件读写 │ safeStorage 加解密 │ 原生对话框         │
│   应用菜单 │ 单实例锁 │ 自动更新(预留) │ LLM 代理请求(可选)             │
└──────────────────────────────────────────────────────────────────────┘
```

### 1.3 为什么 LLM 请求走主进程

| 方案 | 问题 |
|---|---|
| 渲染进程直连 | ① 受 CORS 限制，部分厂商接口拒绝浏览器来源；② 密钥出现在渲染层可被 DevTools 观测；③ 无法自定义超时/重试的底层控制 |
| **主进程代理（选用）** | ① 无 CORS 问题；② 密钥只在主进程内存中使用，渲染层永远拿不到明文；③ 可统一做重试、超时、流式转发 |

> 结论：**所有外网 LLM 请求由主进程发出**，渲染层通过 IPC 订阅流式增量。这是本项目安全模型的关键一环。

## 2. 进程模型

### 2.1 主进程（Main）

**职责边界**：只做「渲染层做不了或不该做的事」，不含任何业务 UI 逻辑。

| 模块 | 职责 | 关键 API |
|---|---|---|
| `windowManager` | 创建/恢复主窗口，记忆窗口尺寸 | `BrowserWindow` |
| `projectFs` | 项目文件的读写、另存、最近项目列表 | `fs/promises` |
| `secureStore` | API 密钥加密存取 | `safeStorage.encryptString/decryptString` |
| `llmProxy` | 转发 LLM 请求，流式回传 | `net`/`fetch` |
| `dialogs` | 打开/保存文件、选择目录、确认框 | `dialog` |
| `menu` | 中文应用菜单、快捷键注册 | `Menu` |
| `singleInstance` | 防止多开导致项目文件冲突 | `app.requestSingleInstanceLock` |

### 2.2 预加载层（Preload）

**设计原则**：`contextIsolation: true` + `nodeIntegration: false` + 只暴露**语义化方法**。

```ts
// preload/index.ts —— 只暴露语义方法，绝不暴露 ipcRenderer
import { contextBridge, ipcRenderer } from 'electron'

const INVOKE = <T>(ch: string, ...args: unknown[]) =>
  ipcRenderer.invoke(ch, ...args) as Promise<T>

contextBridge.exposeInMainWorld('api', {
  project: {
    list:    () => INVOKE<ProjectMeta[]>('project:list'),
    open:    (id: string) => INVOKE<ProjectFile>('project:open', id),
    save:    (p: ProjectFile) => INVOKE<SaveResult>('project:save', p),
    saveAs:  (p: ProjectFile) => INVOKE<SaveResult>('project:saveAs', p),
    remove:  (id: string) => INVOKE<void>('project:remove', id),
    export:  (req: ExportRequest) => INVOKE<ExportResult>('project:export', req),
  },
  config: {
    get:  () => INVOKE<ConfigPublic[]>('config:get'),
    save: (c: ConfigInput) => INVOKE<ConfigPublic>('config:save', c),
    test: (c: ConfigInput) => INVOKE<TestResult>('config:test', c),
    activate: (id: string) => INVOKE<void>('config:activate', id),
  },
  llm: {
    chat:      (req: ChatRequest) => INVOKE<ChatResult>('llm:chat', req),
    chatStream:(req: ChatRequest, token: string) => INVOKE<void>('llm:chatStream', req, token),
    onChunk:   (cb: (e: ChunkEvent) => void) =>
      ipcRenderer.on('llm:chunk', (_e, payload) => cb(payload)),
    onDone:    (cb: (e: DoneEvent) => void) =>
      ipcRenderer.on('llm:done', (_e, payload) => cb(payload)),
    abort:     (token: string) => INVOKE<void>('llm:abort', token),
  },
  app: {
    info: () => INVOKE<{ version: string; platform: string; encrypted: boolean }>('app:info'),
    openExternal: (url: string) => INVOKE<boolean>('app:openExternal', url),
    relaunch: () => INVOKE<void>('app:relaunch'),
    /** 把渲染层的主题色同步给原生窗口（底色 / Win 标题栏按钮区 / color-scheme） */
    setTheme: (o: { bg: string; symbol: string; dark: boolean }) => INVOKE<boolean>('app:setTheme', o),
  },
})
```

**安全红线**：绝不暴露 `ipcRenderer` 本体、`require`、`process`、`fs` 原始对象。所有通道名硬编码在 preload，渲染层无法构造任意通道。

### 2.3 渲染进程（Renderer）

React 18 + TypeScript。按「视图层 / 状态层 / 领域服务层」三分：

| 层 | 内容 | 约束 |
|---|---|---|
| 视图层 | React 组件，只消费状态、抛事件 | **不直接改 JSON**，只 dispatch action |
| 状态层 | Zustand store，持有 Design JSON 与编辑器状态 | **JSON 变更的唯一入口** |
| 领域服务层 | 渲染器、选择引擎、拖拽引擎、导出引擎、LLM 客户端 | 纯函数/无状态优先，便于测试 |

## 3. IPC 协议设计

### 3.1 通道命名规范

`<domain>:<action>`，全小写驼峰，禁止通配。

| 域 | 通道 | 方向 | 说明 |
|---|---|---|---|
| project | `project:list` / `open` / `openByDialog` / `save` / `saveAs` / `remove` / `revealInFolder` / `defaultDir` | R→M 请求响应 | 项目文件操作 |
| config | `config:get` / `save` / `remove` / `setDefault` / `test` | R→M 请求响应 | 模型配置 |
| llm | `llm:chat` / `llm:chatStream` / `llm:abort` | R→M 请求响应 | 单次对话 / 流式 / 中断 |
| llm | `llm:chunk` / `llm:done` / `llm:error` | M→R 推送 | 流式增量、结束、错误 |
| export | `export:pickTarget` / `export:write` | R→M 请求响应 | 导出目标选择与落盘 |
| app | `app:info` / `app:openExternal` / `app:relaunch` / `app:setTheme` | R→M 请求响应 | 版本信息、外链、重启、原生窗口配色同步 |

### 3.2 统一响应信封

```ts
type IpcResult<T> =
  | { ok: true; data: T }
  | { ok: false; code: ErrorCode; message: string; detail?: string }

type ErrorCode =
  | 'E_FS_PERM'      // 文件权限不足
  | 'E_FS_NOTFOUND'  // 项目不存在
  | 'E_FS_CORRUPT'   // 项目文件损坏
  | 'E_NET'          // 网络不可达
  | 'E_AUTH'         // 密钥/鉴权失败
  | 'E_TIMEOUT'      // 超时
  | 'E_RATE_LIMIT'   // 限流
  | 'E_MODEL'        // 模型名不存在/不支持
  | 'E_PARSE'        // 返回内容无法解析
  | 'E_SCHEMA'       // 校验不通过
  | 'E_ABORTED'      // 用户中断
  | 'E_UNKNOWN'
```

**原则**：主进程**永不抛异常穿透 IPC**，一律转为 `IpcResult`，保证渲染层拿到的是可判定的结构。错误码直接驱动 UI 引导文案（见 S2-4 §5）。

### 3.3 流式协议

```ts
interface ChunkEvent { token: string; delta: string; index: number }
interface DoneEvent  { token: string; content: string; usage?: TokenUsage; ms: number }
interface ErrorEvent { token: string; code: ErrorCode; message: string }
```

- 每次请求生成唯一 `token`，用于中断（`llm:abort`）与多请求隔离。
- 渲染层按 `token` 路由到对应 UI 区块（生成流 vs 增强流）。
- 主进程做**增量节流**（≥16ms 合并一次推送），避免高频 IPC 打爆主线程。

## 5. 状态管理设计

### 5.1 Store 划分与权责

| Store | 持有 | 关键约束 |
|---|---|---|
| `project.store` | **Design JSON 全文**（pages / tokens / assets / meta） | 唯一数据源。所有编辑最终落到这里 |
| `editor.store` | 选区、悬停、当前工具、缩放/平移、吸附开关、面板折叠 | 纯 UI 态，**不进入项目文件** |
| `history.store` | undo/redo 栈（JSON 快照 + patch） | 订阅 project.store 的「事务化提交」 |
| `config.store` | 模型配置列表、当前激活项、连通状态 | 密钥仅存 id 引用，明文在主进程 |
| `ui.store` | 模态框、Toast、加载态、向导步骤 | 瞬时态 |

### 5.2 JSON 变更纪律（关键）

```ts
// ✅ 唯一推荐路径：通过 action 提交事务
projectStore.applyPatch(patch, { label: '移动图层', coalesceKey: 'drag:node-123' })

// ❌ 禁止：直接改 JSON
projectStore.project.pages[0].root.children[2].layout.position.x = 100
```

**为什么**：直接改会绕过历史栈与脏标记，导致 Undo 失灵、保存遗漏。所有写操作必须走 `applyPatch`，由它统一完成：① 生成反向 patch 入栈；② 标记脏页；③ 触发局部重渲染。

### 5.3 历史栈策略

| 项 | 设计 |
|---|---|
| 记录粒度 | 事务（一次用户意图 = 一条历史），非每次鼠标移动 |
| 合并机制 | 连续同类操作按 `coalesceKey` 合并（如拖拽全过程合并为一条） |
| 上限 | 100 步，超出丢弃最旧 |
| 存储形态 | 反向 patch 栈（省内存），非全量快照 |
| 覆盖范围 | 编辑 / 组件插入 / 图层增删改 / Token 变更 / 页面增删（**不含**缩放平移等视图态） |

## 6. 渲染管线

### 6.1 渲染路径

```
Design JSON (node tree)
   │  ① 解析：展开 token 引用，合并可变样式
   ▼
Resolved Node Tree（样式已扁平化）
   │  ② 递归转 React 元素（组件映射表 node.type → <CanvasNode>）
   ▼
iframe DOM（沙箱隔离，样式不泄漏）
   │  ③ 交互层叠加（选区框、悬停框、参考线、拖拽手柄）
   ▼
可视画布
```

**为什么用 iframe 隔离**：设计稿里必然出现 `body`、`*`、全局字体等选择器，如果直接渲染在主文档会污染应用自身 UI。iframe 让设计稿拥有独立 CSS 作用域，同时天然是个「预览环境」，预览模式与编辑模式共用同一套渲染器。

### 6.2 局部重渲染策略

| 变更类型 | 重渲染范围 |
|---|---|
| 单节点样式/位置 | 仅该节点（`React.memo` + 节点 id 作 key） |
| 节点子树增删 | 该子树 |
| Token 变更 | 依赖该 Token 的节点集合（渲染前建立 token→nodes 反查索引） |
| 页面切换 | 整页（不可避免，但可加骨架屏） |

### 6.3 编辑态性能手法

| 手法 | 用途 |
|---|---|
| `transform: translate()` 位移 | 拖拽时不触发 layout 重排 |
| `will-change: transform` | 提升为合成层 |
| 拖拽中「幽灵层」 | 拖动只移动一个占位框，松手才提交真实 patch |
| `requestAnimationFrame` 节流 | 参考线/吸附计算按帧节流 |
| 图层树虚拟滚动 | 200+ 图层不卡顿 |

## 7. 构建与打包

### 7.1 技术选型

| 项 | 选择 | 理由 |
|---|---|---|
| 桌面壳 | Electron | 本机 Rust/MSVC 缺失，Tauri 排除（§0 已实测） |
| 构建 | Vite | 冷启动快，HMR 好 |
| 语言 | TypeScript | Schema 契约需要类型约束 |
| UI | React 18 | 生态成熟，组件化契合渲染器需求 |
| 状态 | Zustand | 轻量、无 Provider 嵌套、易于在服务层外访问 |
| 样式 | CSS 变量 + CSS Modules | 设计 Token 天然适合 CSS 变量；不引入重型 CSS-in-JS 以保性能 |

### 7.2 构建流程

```
开发:  vite dev (渲染层 HMR)  +  electron 监听 electron/ 目录重启
构建:  vite build → dist/renderer
       tsc 编译 electron/ → dist/electron
       electron-builder 打包 → release/
```

## 8. 安全策略

| 项 | 措施 |
|---|---|
| 上下文隔离 | `contextIsolation: true`、`nodeIntegration: false`、`sandbox: true` |
| IPC 白名单 | 通道名硬编码于 preload，渲染层无法构造任意通道 |
| 密钥保护 | `safeStorage` 加密后落盘（`config.enc`），渲染层只见 `keyRef` |
| 外链拦截 | `setWindowOpenHandler` 一律 `deny`，需跳转则走 `shell.openExternal` 且限定 https |
| CSP | 渲染层设置 `Content-Security-Policy`，禁止内联脚本执行（设计稿在 iframe 内，用 `sandbox` 属性隔离） |
| 本地文件访问 | 仅允许访问「项目目录 + 用户显式选择的路径」，路径做规范化校验防目录穿越 |

### 8.1 密钥流转（重点）

```
用户输入密钥
  → 渲染层 config:save（密钥在传输对象中一次性传递）
  → 主进程 safeStorage.encryptString → 存 config.enc
  → 主进程回传 { keyRef: 'cfg_1', keyMasked: 'sk-****abcd' }
  → 渲染层从此只持有 keyRef，无法还原明文
  → 发起 LLM 调用：渲染层传 keyRef，主进程按 keyRef 解密取明文
```

## 9. 关键技术决策记录（ADR 摘要）

| # | 决策 | 备选 | 结论与理由 |
|---|---|---|---|
| A-1 | 桌面壳 Electron | Tauri | Electron。Tauri 需 Rust+MSVC，本机缺失 |
| A-2 | 数据源 JSON | 直接操作 DOM / 虚拟 DOM 树 | JSON。导出零损耗、编辑可回溯、AI 输出稳定 |
| A-3 | 画布渲染 DOM | Canvas 2D / WebGL | DOM。Stitch 产物本就是 HTML/CSS，DOM→HTML 保真度最高 |
| A-4 | LLM 请求走主进程 | 渲染层直连 | 主进程。规避 CORS、隔离密钥、统一重试 |
| A-5 | 样式用 CSS 变量 | CSS-in-JS | CSS 变量。Token 变更传播零成本，性能优 |
| A-6 | 拖拽自研 Pointer Events | 第三方库（moveable 等） | 自研。需要与 JSON 事务、吸附、历史栈深度耦合，第三方改造成本更高 |
| A-7 | iframe 隔离设计稿 | Shadow DOM | iframe。完整文档作用域，且可作预览沙箱 |
