## 2. 核心架构：Design JSON 是唯一数据源

所有能力都围绕一份 `DesignJSON` 收敛，不存在第二份状态：

```
                 ┌─────────────────────┐
   AI 生成  ────►│                     │────► 画布渲染
   可视化编辑 ──►│    Design JSON      │────► 预览
   打开项目  ────►│  （唯一数据源）      │────► 导出（PNG/SVG/HTML/JSON）
                 └─────────────────────┘
```

渲染实现**只有一份**：`services/render/node.ts`（节点 → HTML 字符串）+ `services/render/tokens.ts`（TokenMap）。
画布、预览、导出三处共用同一实现，从根本上消除了「画布所见 ≠ 导出所得」的问题。

## 3. T5 · AI 生成引擎

### 3.1 三阶段流水线

| 阶段 | 职责 | 失败策略 |
|---|---|---|
| A · 规划 | 需求 → 页面信息架构（页面清单 / 区块 / 跳转 / 设备 / 风格方向） | 失败即终止（后续无意义） |
| B · Token 定稿 | 定稿一套完整设计 Token，供所有页面复用 | **失败不致命** → 回退内置预设，仅告警 |
| C · 逐页生成 | 依 Token 逐页产出 Design JSON | **单页失败跳过**，其余照常产出；全部失败才报错 |

### 3.2 五级容错链路

针对模型输出不可控的现实，构建逐级兜底：

1. **抽取** `extractJson` —— 从废话、Markdown 围栏、前后缀中抠出 JSON
2. **宽松解析** `lenientParse` —— 容忍尾逗号、单引号、注释等非严格 JSON
3. **结构校验** `validate*Payload` —— 校验必需字段，错误信息带阶段前缀
4. **语义修补** `repairNode` / `repairPagePayload` —— 补 id / 补 type / 包裹异常 root / 兜底空白容器
5. **修复重试** —— 把上一次原始输出与错误原因回灌模型，请求重新生成（最多 2 次）

### 3.3 跨页一致性保障

- **节点 id 跨页去重**：`dedupeIdsAcrossPages` 防不同页生成相同 id
- **跳转规范化**：`normalizeFlows` 过滤掉指向不存在页面 / 不存在源节点的死跳转，并补全 `fromPage`
- **页面坐标自动错开**：按序号 `x = i * (canvas.width + 40)` 排布，避免画布上重叠

### 3.4 提示词增强（F-PE-01）

- **L0~L3 输入分级**：按信息完备度（结构化 / 页面数 / 风格 / 设备）判定，给出分级建议
- **8 区块固定模板**：统一输出结构，跨场景一致
- **双通道**：本地启发式（未配模型时可用）/ LLM 增强
- **意图保全校验（R-13 红线）**：抽取原文实体，校验增强结果是否遗漏；遗漏超阈值则**自动回退**本地启发式，绝不篡改用户原始意图
- **对标视图**：原文 vs 增强 并列展示，用户可一键填入输入框

## 4. T6 · 可视化编辑器内核

### 4.1 事务化提交

所有变更必须经 `commit(label, mutator, { coalesceKey })`：

- `mutator` 接收**克隆后**的 design，返回新对象 → 天然不可变，杜绝隐式共享
- 自动记录**反向 patch** 入历史栈（`MAX_HISTORY = 100`）
- `coalesceKey` 合并连续同类操作 —— 拖拽全过程只占 **1 条历史**，一次撤销即回退整段拖动

### 4.2 画布交互

基于 Pointer Events 自研，不依赖任何第三方画布库：

- 缩放 / 平移（`transform: translate + scale`）
- 选中 / 多选 / 拖拽移动 / resize
- 点击页面区域自动切换 `activePageId`

## 6. T8 · 导出引擎 + 打包

### 6.1 五种导出格式

| 格式 | 实现要点 |
|---|---|
| **PNG** | 主进程隐藏 `BrowserWindow` 光栅化（Chromium 自身渲染），**不依赖任何第三方库**；单页失败不影响其余页 |
| **SVG** | `foreignObject` 包裹 HTML，最大兼容 |
| **HTML 单文件** | 多页汇总 + tab 切换，自包含 |
| **HTML 工程** | 每页独立文件 + `index.html` 导航 + `design.json` 源文件，页面间跳转可点击 |
| **JSON** | 设计源文件，可二次编辑 |

### 7.3 测试驱动修复的真实缺陷

编写测试过程中，测试**反向暴露**了实现层面的问题并已修复：

1. **规划阶段空 pages 的错误文案误导** —— 原报「模型输出无法解析」，易让人以为是 JSON 语法问题；`validatePlanPayload` 改为明确提示「规划结果未包含任何页面」，并给所有阶段错误加阶段前缀。
2. **增强器 L3 分级判定过松** —— 完整描述被判为 L2，重写为按信息完备度（结构化 + ≥2 页 + 有风格 + 有设备）判定。
3. **页面识别漏项** —— 「商品详情」不含「页」字被漏，新增 `detectPages` 全文扫描。
4. **实体抽取把整句当实体** —— 改为按标点/连接词切分 + 剥离尾部泛化后缀。
5. **启动自检进程挂死（本轮新发现）** —— `app.exit()` 是同步调用，在无 GPU / 管道 stdio 环境可能 hang 住，导致其后的 `process.exit` 强退兜底**注册不上**。修复：**先注册强退定时器，再调 `app.exit`**；同时 `smoke.mjs` 改为按输出标记（`[smoke] RESULT:PASS`）判定结论 + 超时强杀进程树，不再依赖子进程「自觉退出」。
