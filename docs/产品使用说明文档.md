## 1. 这是什么

一个**完全运行在本机的望舒**。你用自然语言描述想要的产品，它生成可编辑的界面原型，你可以像用设计工具一样拖拽调整，最后导出为 HTML、图片或设计源文件。

### 能做什么

- **从一句话到多页原型**：描述需求，自动规划页面结构、定稿设计规范、逐页生成
- **真实可视化编辑**：拖拽移动、缩放调整、改属性、改文案，全部实时生效
- **全局设计一致性**：改一个主色，所有引用它的元素同步更新
- **可点原型**：配置页面跳转后，预览时点击真实跳转，可验证完整流程
- **多方案对比**：为同一页面生成多个差异化变体，挑选后采纳
- **五种导出格式**：HTML 单文件 / HTML 工程 / PNG / SVG / 设计源文件

### 三条设计原则

| 原则 | 含义 |
|---|---|
| **纯本地** | 无服务器、无账号、无遥测。只有你主动配置模型时才会产生网络请求 |
| **数据即文件** | 所有设计保存在标准 JSON 中，你可以随时查看、备份、手工修改 |
| **所见即所得** | 画布、预览、导出使用同一套渲染引擎，导出结果与画布完全一致 |

## 2. 安装与启动

### 便携绿色版（推荐）

1. 找到 `望舒-1.1.0-portable.exe`
2. 双击运行

**无需安装**，不写注册表，不产生残留。可以放在 U 盘里随身携带。

### 安装版

运行 `望舒 Setup 1.1.0.exe`，按向导完成安装，可选择安装目录。

### 首次启动

首次启动会自动加载一个示例项目（移动端登录页 + 首页，含页面跳转），以便你立刻看到成品效果并体验编辑。

此时还没有配置模型，但**所有编辑、预览、导出功能都可以正常使用**——只是无法用 AI 生成新内容。

## 4. 完整工作流（五步）

### 第一步 · 配置模型

按 `Ctrl + ,` 打开配置面板，选择服务商、填入密钥、测试连接、保存。

> 详细说明见《大模型配置操作指南》。没有密钥也可以跳到第三步，先用示例项目体验。

### 第二步 · 描述需求

在左上角输入框用自然语言描述。**越具体越好**：

```
❌ 不好：做个 App

✅ 可以：一个外卖点单 App，包含首页推荐、菜品详情和购物车三个页面

✅ 更好：一个面向大学生的外卖点单 App，包含首页推荐、菜品详情、购物车三个页面。
        风格清新简洁，主色橙色，移动端展示，首页要有搜索框和分类入口。
```

### 第三步 · 增强提示词（可选但推荐）

如果描述比较简短，先点「增强提示词」（`Ctrl + K`）。系统把口语化描述改写为结构化的需求简报，包含 8 个区块：产品概述、目标用户与场景、页面结构、各页面关键区块、核心交互、视觉风格、设备与尺寸、待确认事项。

**增强结果直接就地替换输入框里的内容**——不弹对比面板，也不让你在原版与增强版之间二选一。少一次选择，也少一次误操作。改写后输入框下方出现一条状态提示：

```
✨ 已增强 · L1 口语描述 · 补全了：设备与尺寸 · 由模型生成     [撤回]  [再次增强]
```

- **撤回**（`Ctrl + Z`）：逐条弹出，连按可一路退回最早的原文
- **再次增强**：模型有随机性，可换个版本
- 想微调就直接在输入框里改——改写后的文字就是普通文本，随便编辑

> 「撤回」只在**你尚未手动改动**增强结果时才接管 `Ctrl + Z`；一旦你开始编辑，`Ctrl + Z` 交还给文本框自身的撤销，不会抢走你的操作。

### 第四步 · 生成

按 `Ctrl + Enter` 或点「生成」。生成分三步执行，界面上会实时显示进度：

| 阶段 | 做什么 | 耗时占比 |
|---|---|---|
| ① 规划信息架构 | 决定要有哪些页面、每页有哪些区块 | 约 15% |
| ② 定稿设计规范 | 确定配色、字阶、间距、圆角 | 约 10% |
| ③ 逐页生成 | 按页生成具体元素 | 约 75% |

**阶段 ② 是关键**：设计规范先定稿，后续所有页面都引用它，这是保证跨页风格一致的机制基础。

生成过程中可随时点「取消生成」中断。

### 第五步 · 编辑与导出

生成完成后进入编辑。调整满意后按 `Ctrl + E` 导出。

## 5. 核心功能详解

### 5.1 AI 生成

**生成粒度**：一次生成整个项目（2~6 个页面）。

**输入建议**：
- 明确产品类型（App / 小程序 / 网页 / 后台）
- 列出需要的页面
- 说明视觉倾向（配色、气质）
- 点名特殊要求（要图表、要地图、要有搜索）

**示例提示词**：

```
一个健身打卡 App，包含首页、训练记录、个人中心三个页面。
深色科技风格，主色青蓝。首页要有今日训练卡片和进度环，
训练记录页用列表展示，个人中心要有头像和统计数字。
```

**为什么需要 Token 先定稿**：如果每页独立生成，模型会在每页自行决定颜色，导致第一页是电光蓝、第二页变成靛蓝。先定稿一套 Token 再从同一套 Token 出发生成各页，是解决这个问题的结构性方案。

### 5.2 提示词增强

**触发**：只能手动点击「增强提示词」或按 `Ctrl + K`。**不会自动触发，也不做静默改写**。

**改写方式**：结果**就地覆盖输入框**，不保留「原文 / 增强版」两套内容。改写后随时可按 `Ctrl + Z`（或点状态条上的「撤回」）逐条退回，原文不会丢，也不会出现「这次生成到底用的是哪一版」的歧义。

**输入分级**：系统会判断你的输入属于哪一级，并在输入框下方给出建议：

| 级别 | 特征 | 建议 |
|---|---|---|
| L0 | 极短（≤6 字） | 信息太少，增强结果会大量标注推断 |
| L1 | 口语化碎片 | 强烈建议增强 |
| L2 | 半结构化（缺风格或设备说明） | 建议增强 |
| L3 | 信息完整 | 无需增强 |

**推断标注**：增强结果中，凡是系统替你补全的内容都会标注 `[推断]`，例如：

```
[推断] 未指定设备，按移动端处理
[推断] 未指定视觉风格，采用「清透蓝」中性配色
```

需求内部有矛盾时标注 `[冲突]` 并说明，**不会替你擅自取舍**。

**意图保全**：增强完成后会做一次校验——检查你说过的关键点是否都还在增强结果里。如果发现遗漏，会**回退到本地规则增强的结果**（注意：不是放弃增强，也不是退回原始描述），并在状态条中注明「增强结果可能遗漏了「…」，已回退到本地规则」，避免「增强反而丢需求」。

**没配置模型也能用**：未配置模型、模型调用失败、或模型输出格式异常时，增强会自动降级为**本地规则增强**——不联网也能补全设备、风格、页面结构等常见缺口；此时状态条不会出现「由模型生成」。

### 5.3 可视化编辑

#### 选中

- 点击画布上的元素选中
- 按住 `Shift` 点击可多选
- 点击画布空白处取消选中
- 在左栏「图层」页签点击也可选中

#### 移动

直接拖动元素。拖动时有以下辅助：

- **8px 网格吸附**：自动对齐到网格
- **对齐吸附**：靠近页面左边缘、水平中线、右边缘时自动吸附，并显示粉色辅助线
- **按住 `Shift`**：锁定为水平或垂直移动

#### 缩放元素

选中后，四角与四边共 8 个手柄可拖动调整尺寸。按住 `Shift` 拖角手柄可保持宽高比。

#### 改属性

在右栏「属性」面板：

| 分组 | 可调整内容 |
|---|---|
| **布局** | 定位模式（自由/弹性/网格）、坐标、宽高、四向内边距、主轴与交叉轴对齐、元素间距 |
| **外观** | 填充色、描边色与粗细、圆角、透明度 |
| **文字** | 字号、字重、行高、字间距、水平对齐、文字颜色 |
| **内容** | 文本内容、按钮文字、输入框占位提示、图片地址、图表数据、标签文字等 |

文本类的属性输入框支持**连续编辑合并为一次撤销**（在输入框内连续打字不会产生几十条历史记录）。

#### 画布导航

| 操作 | 效果 |
|---|---|
| 滚轮 | 上下平移画布 |
| `Shift` + 滚轮 / 横向滚轮 | 左右平移 |
| `Ctrl` + 滚轮 | 以光标位置为中心缩放 |
| 按住空格拖动 | 平移画布 |
| 中键拖动 | 平移画布 |
| `Ctrl + 1` | 适应窗口 |
| `Ctrl + 0` | 恢复 100% |

#### 复制与删除

- `Ctrl + D` 复制选中元素（副本偏移 16px）
- `Delete` 删除选中元素
- 图层行悬停时出现眼睛与锁图标，可隐藏/锁定元素

### 5.4 设计 Token 与全局换肤

Token 是一套命名的设计变量。元素属性可以**引用** Token 而不是写死值：

```
$color.primary     主色
$color.text        正文色
$radius.md         中等圆角
$space.lg          大间距
```

**引用 Token 的好处**：改 Token 的定义，所有引用它的元素**自动更新**。

#### 操作

1. 取消所有选中，右栏「属性」面板显示项目信息
2. 在「设计 Token」区域找到「主色」，点击色块修改
3. 画布上所有引用 `$color.primary` 的元素立即变色

#### 怎么让元素引用 Token

在属性面板的颜色输入框里，可以直接输入 `$color.primary`，或点击下方的 Token 快捷按钮（显示为小色块 + Token 名）。

**建议**：优先用 Token 而非写死颜色。这样后期换肤只需改一处，也让导出的设计更规范。

### 5.5 多页面与跳转

#### 管理页面

在左栏「页面」页签：

- **新建页面**：生成一个空白页（含一个纵向弹性根容器）
- **复制页面**：完整复制页面内容
- **双击页面名**：重命名
- **删除页面**：删除（至少保留一个页面）

画布上所有页面**并排展示**，当前编辑的页面有高亮边框与页面名标注。点击任意页面即可切换。

#### 配置跳转

1. 选中一个可点击的元素（按钮、列表项等）
2. 在右栏「属性」面板底部找到「点击跳转」
3. 从下拉框选择目标页面

一个元素目前支持一个跳转目标。已配置的跳转显示在列表中，可删除。

#### 查看全部跳转

右栏「跳转」页签显示：

- **跳转关系列表**：源页面 → 目标页面、触发元素、触发方式
- **页面关系图**：用连线可视化页面之间的跳转拓扑

### 5.6 设计变体

不满意当前设计？生成几个差异化方案对比挑选。

#### 使用

1. 在画布工具栏点击「变体」
2. 勾选差异化维度（可多选）：

| 维度 | 差异内容 |
|---|---|
| 布局结构 | 重新组织区块排布与信息层级 |
| 配色方案 | 调整色彩与氛围，保持结构不变 |
| 字体排版 | 改变字阶、字重与间距节奏 |
| 文案内容 | 换一套措辞，信息点保持一致 |
| 视觉元素 | 调整图形、图标与占位方式 |

3. 选择方案数量（2~4 个）
4. 点击「生成变体」
5. 并排对比：**最左侧始终是你的当前方案**，右侧是变体
6. 点击选中满意的方案，点「采纳选中方案」

**注意**：变体生成比单页生成更耗时（需要模型输出多个完整设计）。生成变体不会修改全局设计 Token，只有采纳后才会应用。

### 5.7 原型预览

按 `Ctrl + P` 或点画布工具栏的「预览」。

预览模式下：

- 页面以真实尺寸（按窗口自适应缩放）展示
- **可点击元素会显示蓝色虚线框**
- 点击可交互元素真实跳转，带过渡
- `Backspace` 返回上一页
- 顶部下拉框可直接切换到任意页面
- `Esc` 退出预览

**这是与静态设计稿的核心区别**：可以真正走一遍完整流程，验证跳转逻辑是否合理。

### 5.8 导出

按 `Ctrl + E` 打开导出面板，五种格式：

| 格式 | 产物 | 适合场景 |
|---|---|---|
| **HTML 单文件** | 一个 `.html`，含全部页面与切换标签 | 发给别人看原型、放进汇报文档 |
| **HTML 工程** | 每页一个 `.html` + `index.html` 导航 + `design.json` | 交给前端开发实现 |
| **PNG 图片** | 每页一张 2 倍分辨率图片 | 放入设计评审文档 |
| **SVG 矢量图** | 首个页面的矢量图 | 需要无损缩放或继续编辑 |
| **Design JSON** | 完整设计源文件 | 备份、版本管理、程序化处理 |

#### 导出产物特点

- **完全自包含**：HTML 内联了全部样式，不依赖任何外部文件或网络
- **零依赖打开**：双击 HTML 即可在任意浏览器查看，无需本工具
- **真实交互**：多页导出的 HTML 保留了页面跳转逻辑

导出完成后会自动打开所在文件夹。

### 5.9 外观主题

点击顶栏右侧的**调色盘图标**，在四套内置主题间切换，无需重启：

| 主题 | 明暗 | 说明 |
|---|---|---|
| **夜阑** | 深色 | 默认。低亮度蓝调，长时间盯屏更省眼 |
| **晨光** | 浅色 | 明亮清爽，适合白天或投屏演示 |
| **沧海** | 深色 | 蓝青配色，冷色调偏好者适用 |
| **墨韵** | 浅色 | 淡紫灰调，柔和不刺眼 |

要点：

- **即时生效**：点选即切换，画布、面板、弹窗、状态栏同步换色，无需重启
- **自动记住**：选择保存在本机，下次打开自动恢复
- **不影响产出**：主题只改变**工具外壳**的颜色。你设计稿的颜色来自项目的「设计 Token」，
  导出产物完全不受界面主题影响——换主题不会把设计稿改成深色
- **原生窗口同步**：窗口底色与标题栏按钮区一并跟随，不会出现「外面浅色、标题栏还是黑条」的割裂感

> 扩展阅读：主题对应的颜色变量集中定义在 `app/src/styles/tokens.css`，新增一套主题只需追加一个
> `[data-theme="xxx"]` 块并在 `app/src/stores/theme.store.ts` 的 `THEMES` 中登记一项。

## 8. 常见问题

**Q：没有 API 密钥能用吗？**
可以。所有编辑、预览、导出功能都能用。只有 AI 生成需要模型。可以先加载内置示例项目体验完整流程。

**Q：生成的界面不是我想要的样子？**
三个办法：① 增强提示词后再生成（最有效）；② 生成变体对比挑选；③ 直接手动编辑调整。

**Q：为什么多个页面的风格不一致？**
正常情况下不会——设计规范（Token）在生成前统一定稿，所有页面共享。如果仍出现不一致，可能是模型未严格遵循 Token，可尝试用能力更强的模型，或在提示词中明确指定主色。

**Q：能让元素看起来更像原生控件吗？**
本工具生成的是设计稿而非可运行代码。渲染引擎刻意保持简洁的视觉表达，重点是结构与层级，不是像素级拟真。

**Q：导出后打开发现字体不一样？**
导出 HTML 使用系统字体族（Segoe UI / 微软雅黑 / PingFang SC 等）。如果设计稿用了特定字体且目标机器未安装，会回退到系统字体。

**Q：改了一个元素，为什么位置跳了？**
弹性布局中元素位置由布局规则决定。一旦你手动拖动某个元素，它会自动脱离弹性流变为自由定位（这是刻意设计——否则拖动会被布局规则立刻「拉回去」）。

**Q：撤销为什么一次跳很多步？**
连续同类操作会被合并（比如在输入框里连续打字、一次完整拖拽），这是为了保持历史列表可用。每次拖动、每次输入停顿都算一步。

**Q：支持团队协作吗？**
当前版本是纯本地单人工具。项目文件可以通过网盘、Git 等方式自行共享，但不提供实时协作。

**Q：数据会上传吗？**
只有你主动配置模型并点击生成时，需求描述会发送给你自己配置的模型服务商。项目数据、编辑内容、密钥都不会上传。使用本地 Ollama 时可实现完全离线。

## 9. 设计理念说明

### 为什么以 JSON 为唯一数据源

传统设计工具的内部状态是复杂对象图，导致三个后果：AI 集成困难、导出必然失真、版本管理几乎不可能。

本工具把**所有设计表达为一个 JSON 文档**，AI 生成 = 产出 JSON，可视化编辑 = 修改 JSON，画布与导出 = 消费 JSON。

由此获得：
- AI 与编辑器天然解耦，换模型不影响编辑能力
- 导出零损耗（导出就是序列化同一份数据）
- 项目文件可 diff、可手工修改、可程序化生成

### 为什么画布、预览、导出共用一套渲染

如果三者各自实现，必然出现「画布上好好的，导出就错位」的问题。共用同一个渲染函数使「所见即所得」成为**结构性保证**而非需要持续维护的一致性问题。

### 为什么不自动改写你的提示词

自动改写用户输入有「好心改需求」的风险——你说了三件事，系统理解成两件，生成结果不对，而你甚至不知道发生了什么。

因此增强功能始终是**显式触发**的：改写结果就地可见、可逐条撤回，并配有意图保全校验。系统替你做的是**补充缺口**，而不是替你决定需求——且它补了什么，状态条会当场告诉你。
