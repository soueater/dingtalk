**F-ST-03「生成设计变体」报错的根因（5 条，按确定性排序）：**
1. **主因**：`variants.ts:71-82` 的 Prompt 要求**一次请求返回 N 个完整页面树**，且 `maxTokens` 硬编码 `12000`（`variants.ts:110`）。一页约 5-10K tokens，3 个变体必然截断 → `closeBrackets` 补出语法合法但语义残缺的 JSON → 报「模型未返回任何变体」。**是必然，不是偶发。**
2. `maxTokens: 12000` 绕过用户配置（默认 8192），且超出部分服务商单次上限 → 400 → 落 `E_UNKNOWN`
3. **变体链路完全没有 `askJson` 式「校验 + 修复重试」**（对比 `generate.ts:47`），零韧性
4. `jsonMode: true` 无条件附 `response_format`（`llm-proxy.ts:93/221`），部分 OpenAI 兼容服务不支持 → 400；Anthropic 分支空内容时返回空串
5. 死代码：`variants.ts:148-151` 的「恢复 Token」只有比较+toast、无恢复动作且条件恒假；`generateNodeVariants`（:165）零调用方

**修复方案**：P0 止血（逐变体独立请求 / 预算保护 `min(cfg, 8192)` / 抽取 `askJson` 公共模块 / jsonMode 按能力启用 / 清死代码）→ P1 根治（变体只输出差异补丁，与 F-ST-04 共用 ops+diff 范式）

### 关键技术决策（易踩坑）

1. **内联 style 优先级悖论**：节点样式走内联 `style`，其优先级高于任何普通类选择器 → `states` 伪类规则必须 ① 用 `[data-id="…"]` 锚定（id 全局唯一）；② **每条声明追加 `!important`**；③ 集中产出进 `<style>` 块。
2. **`slugifyPageId` 必须确定性**：中文无法转 ascii slug，原用 `Date.now()` 会导致重复采纳生成一堆语义重复页面 → 改 **djb2 稳定哈希**（`page_<hash>`），同名恒定，仅冲突时追加序号。
3. **`detectBrokenLinks` 的 `matchPageByText` 要传空 `fromPageId`**：口径是「全局是否已存在该语义页面」，否则「详情页」内部的「详情」文案会自己否定自己，误报缺页。
4. **esbuild 测试打包**：`alias` 拦不住**相对路径**说明符，必须用 `onResolve` plugin；替身状态一律挂 `globalThis`（否则跨 bundle 读到另一份实例）。

### 关闭缺陷根因（报告 §4.12，已按真实代码修正）

- **真实根因**：渲染层 `beforeunload` 里 `preventDefault()` → Electron 向主进程 `webContents` 派发 **`will-prevent-unload`** → **主进程当时无任何监听器** → Chromium 默认「尊重渲染层取消」= 拒绝卸载 → 窗口关不掉且无任何提示。
- **修复**：决策权收归主进程。`electron/main/close-guard-core.ts`（74 行纯函数：`decideClose`/`mapDialogResponse`/`effectOfChoice`/`shouldCloseAfterSave`，零 Electron 依赖）+ `electron/main/close-guard.ts`（副作用：原生三选项对话框 + await 保存结果 + 8s 超时）+ **安全网** `webContents.on('will-prevent-unload', e => e.preventDefault())`（保证永不再关不掉）。渲染层 `src/services/project/close-guard.ts` 降级为协调器（同步 dirty / 回报保存结果），`beforeunload` 仅浏览器调试兜底。
- 回归断言 37 项（① 组 = 8+4+16+9），含「不存在静默拦截状态组合」不变量。
