### 六、凭据排障（**关键环境知识，下次直接照做**）

推送一度「无输出 + SIGTERM 退出」，**不是沙箱拦截**，而是凭据助手挂起：

| 现象 | 真实原因 |
|---|---|
| `git push` 卡住后被 SIGTERM，stdout/stderr 全空 | `credential.helper=helper-selector` 需要弹 GUI 选择框，非交互 shell 下挂死 |
| `git -c credential.helper= push` | 报 `Authentication failed`（此时才是「真没凭据」） |
| `git-credential-manager github login --device --no-ui` | 报 `Cannot prompt because terminal prompts have been disabled`（因为环境里 `GIT_TERMINAL_PROMPT=0`） |
| 去掉该变量后再跑，或 `winpty -Xallow-non-tty` 包一层 | 仍无输出 / `conout != INVALID_HANDLE_VALUE` 断言失败 —— **本 shell 无真实控制台，OAuth 交互走不通** |

**可用做法（已验证）**：凭据其实**已存在 Git Credential Manager 中**，只是带 `path` 查询时会挂起。

```bash
# 1) 不带 path 查询即可拿到（带 path 会触发账号解析并挂起）
printf "protocol=https\nhost=github.com\n\n" | GIT_TERMINAL_PROMPT=0 git-credential-manager get > /tmp/ghcred.txt
chmod 600 /tmp/ghcred.txt

# 2) 用「文件型一次性助手」推送 —— 令牌不进 argv、不进日志
git -c credential.helper= -c "credential.helper=!f() { cat /tmp/ghcred.txt; }; f" \
    push -u origin <branch>

# 3) 用完立即删除含令牌的临时文件
rm -f /tmp/ghcred.txt
```

- 该凭据类型为 `gho_*`（GCM 的 GitHub OAuth App 令牌），账号 `soueater`，`GET /user` 返回 200。
- 判断凭据是否有效：`curl -H "Authorization: Bearer $TOKEN" https://api.github.com/user`。

### 九、两个卡点与解法

**卡点 1：GitHub 拒绝建立 PR**

```
GET /repos/soueater/dingtalk/compare/master...feature/pm-stitch-parity
→ 404  "No common ancestor between master and feature/pm-stitch-parity."
```

**没有共同祖先的分支无法比较，也就无法开 PR。** 解法（非破坏性，保留 `master` 上的一切）：

```bash
git fetch origin
git merge origin/master --allow-unrelated-histories --no-ff -m "merge: ..."
# → Merge made by the 'ort' strategy.  README.md | 1 +   （无冲突）
git push origin feature/pm-stitch-parity
```

合并后 `git merge-base HEAD origin/master` = `a78d1a5`，PR 随即可建。
> 备选（未采用）：`git rebase origin/master` 可得线性历史，但要 `--force` 重写已推送的 3 个提交。本次分支无协作方，其实也可行，只是改写历史不如合并稳妥。

**卡点 2：GitHub MCP 无法建 PR**

```
mcp__github__create_pull_request → 403 Resource not accessible by integration
```

连接的 GitHub App 没有 PR 写权限（读操作正常）。改用 GCM 令牌走 REST API 即可：

```bash
TOKEN=$(sed -n 's/^password=//p' /tmp/ghcred.txt)
curl -X POST -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
     --data-binary @payload.json https://api.github.com/repos/<owner>/<repo>/pulls
```

### 十、教训（补充第六章）

- `git-credential-manager get > file 2>/dev/null` 在**网络抖动（代理 502）**时会**静默产出空文件**，
  随后 push 报 `could not read Username`。**取凭据后必须 `[ -s file ]` 校验非空并重试**，不要盲信退出码。
- 本次出现过一次「push 退出码 0 但远程 ref 未移动」的假成功，靠 `git fetch` + `rev-parse` 比对才发现。
  **结论：推送后一律复核远程 HEAD，不能只看退出码。**
