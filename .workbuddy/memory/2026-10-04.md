### 一、关闭缺陷「仍未修复」的真实原因（重要教训）

用户复测后反馈缺陷仍在。**修复代码本身是有效的**，问题在**交付物滞后**：

| 项 | 时间戳 | asar 是否含修复特征串 `will-prevent-unload` |
|---|---|---|
| 修复源码 `electron/main/close-guard.ts` | 2026-09-30 10:46 | — |
| 旧包 `package/win-unpacked/望舒.exe` | 2026-09-29 18:36 | **0（否）** |
| 新包 `out/win-unpacked/望舒.exe` | 2026-10-04 14:51 | **1（是）** |

**根因：`npm run verify` 只产出 `dist/`，不含 `electron-builder` 打包。** 上轮验证通过后直接交付，用户测的是旧二进制。

**教训（硬性规则，勿再犯）**：改过 `electron/` 或 `src/` 后，**必须重新执行 `electron-builder`，并核验新包 asar 含本次修复的特征串**：
```bash
grep -c "will-prevent-unload" <outDir>/win-unpacked/resources/app.asar   # 应为 1
```

### 二、关闭流程真机实测新增（`scripts/probe-close.mjs`，4/4 通过）

纯函数单测证明不了「真实窗口点关闭会关」，故新增真机探针：
- 原理：`electron/main/close-probe.ts`（env `CLOSE_PROBE` 守卫，生产零副作用）**替换 `dialog.showMessageBox` 按脚本自动作答**，然后 `win.close()`，断言 `closed` 事件是否触发。替换同一 electron 模块对象上的属性 → close-guard 调用时能查到。
- 两个关键坑：
  1. **窗口一关，Electron 立即 `app.quit()`**，把探针的判定代码一起带走 → 需在 `window-all-closed` 里判断 `CLOSE_PROBE` 时不自退；
  2. `win.isDestroyed()` 不如监听 `closed` 事件可靠，判定用后者。
- 4 个场景：clean / dirty+不保存 / dirty+保存并关闭（并校验产物文件真写出）/ dirty+先取消再关闭（验证不会永久卡死）。
- `package.json` 加 `test:close`（= build:electron + probe）。

### 四、自定义设计风格（新能力）

**架构分工**：纯逻辑离线层 vs 模型调用层，便于单测。

| 文件 | 职责 |
|---|---|
| `src/services/design/style-extract.ts` | **纯逻辑**（不 import store/react/electron）：色值工具、CSS 取色、像素量化、调色板→Token、HTML 提炼、载荷归一化 |
| `src/services/ai/spec-from-text.ts` | 唯一联网入口：文字描述 → Tokens（`askJson` + `TEMP.tokens` + `normalizeSpecTokens`） |
| `src/components/panels/SpecPanel.tsx` | 新增「自定义设计风格」区块：三个入口 + 提炼预览 + 命名保存 |

**三种来源**：
1. **文字描述** → 模型（需配置）；
2. **HTML 源码** → 本地解析（`<style>` 块 + `style=""` 属性）；
3. **图片** → 本地像素采样（缩到 320px → canvas `getImageData` → `quantizePixels` 4bit 分箱）。

产物用既有 `createSpec` 存为规范，进入「规范库」，可绑定项目/页面、导出复用、多套并存。

**关键算法决策（含踩坑）**：
- 底色：**优先 `body`/`html`/`:root` 的 `background` 锚点**；无锚点时取「最高频一档里亮度最极端者」，并用「更亮优先」破平局。（踩坑：纯按频次会在计数相同时退化成按色值排序，把 `box-shadow` 的 `#000000` 选成底色）
- 正文色：**先筛对比度 ≥ AA 4.5，其中优先中性色**。（踩坑：按「对比度 × 中性加权」打分时，浅底+蓝主色会让蓝色胜出，正文和主色撞车）
- 主色：饱和度阈值提到 **0.35** 且**排除已选作底色/正文的颜色**。（踩坑：0.25 会把深灰蓝正文色误判为主色）
- 字号：正文优先取 `body/:root` 的 `font-size` 锚点，其次众数；阶梯按比例生成后**强制单调**（`display > h1 > h2 > h3 > body > caption > overline`）。（踩坑：nearest-snap 会让 h2/h3 塌缩成同值；众数在「每档各一次」时退化成最小字号）
- 阴影：**提取数值前先剥掉颜色**，否则 `#000000` 里的 0 会被当成偏移量。
- `pageAnchors`：**先按 `选择器{}` 切块再判断选择器**，不要用带边界字符的正则扫全串（前一次匹配会吃掉边界）。
- `readableOn`：用**明度阈值 0.55** 而非对比度比较（中蓝 `#3B82F6` 上深字对比度 4.83 反超白字 3.68，但按钮惯例配白字且属 AA-large）。
